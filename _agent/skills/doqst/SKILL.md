# 📘 題庫產出防呆流水線 (Do Question)

> **觸發時機**：當使用者呼叫 `/doqst`，或指令涉及「產出題庫 JSON」、「修改題目檔」時執行。

當你被呼叫 `/doqst` 時，你的任務是扮演**題庫兵工廠的嚴格品管員**。請嚴格執行以下流水線步驟：

## 步驟一：讀取規範與 Schema
在產出任何 JSON 之前，強制讀取以下兩份文件：
1. **題庫格式與緩存規範**：`question/README_題庫格式規範.md`
2. **題庫數據理型**：`shared/forms/題庫數據理型.md`
（確認最新的 `answer_index` 規則、JSON 結構與必填欄位）。

## 步驟二：產出 JSON 檔案
根據使用者的需求（例如「產出翰林五下L11」），生成具備 L4 素養水準的考題。
**遵守鐵律**：
- 必須是 0-based `answer_index`。
- `options` 必須剛好 4 個。
- 選項文字長度必須對稱（不可出現長度嚴重偏差的盲猜洞）。
- 必須具備有價值的 `explanation` 與生活化 `scenario`。

## 步驟三：觸發自動化品質閘門 (Quality Gate)
產出 JSON 並存檔後，你必須**主動在終端機 (Terminal)** 執行以下檢驗腳本：
```bash
node scripts/evaluate_question_quality.js --gate {你的題庫檔案路徑}
```

## 步驟四：檢查與糾正
讀取腳本的輸出報表：
- **若出現 L1 (BIAS) 或報錯**：代表格式損壞或長度嚴重失衡。你必須**立刻自行修正並覆寫檔案**，然後重新跑腳本，直到通過為止。
- **若 CQI (平均細緻度) < 6.0 分**：代表題目太簡陋、缺乏解析。你必須加長情境與解析後重新產出。

## 步驟五：同步與回報
腳本檢驗通過後：
1. 同步數據：執行 `node scripts/sync_stats.js`。
2. 若有新課次，更新 `manifest.json` 與對應年級的 `題庫統計表.md`。
3. 向使用者回報：
   > ✅ **出題流水線執行完畢！**
   > - 檔案：`{檔名}`
   > - CQI 平均分數：`{分數}`
   > - QG 等級：`{L1~L5}`
