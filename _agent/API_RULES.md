# 🌐 API 使用與成本控管原則 (API Economics & Usage Policy)

> **最後更新**：2026-03-22 13:30
> **維護者**：Antigravity (Project Manager Agent)

為了平衡開發效率與營運成本，所有涉及外部 LLM API (Gemini, OpenAI, Anthropic 等) 的自動化任務均須遵守本原則。

## 1. 成本監控與記錄規範
- **Token 自動統計**：所有執行大量 API 呼叫的腳本（如 `run_blind_eval.js`）必須具備 Token 統計功能。
- **任務結案報告**：每個 JOB 結案時，必須在報告中列出：
  - 總計消耗 Token 數 (Input / Output)
  - 使用的模型分佈 (Model Distribution)
  - 預估產生費用 (Estimated Cost in USD/TWD)

## 2. 金鑰分級與調速原則
- **[free] 標籤**：未綁卡帳號。強制延遲 10s/題，避免 429 封鎖。
- **[tier1] 標籤**：綁卡帳號（仍享免費配額）。建議延遲 2s/題，平衡速度與安全。
- **[paid] 標籤**：無免費額度之付費帳號。建議延遲 1s/題，追求最高效率。

## 3. 預算配額與警示
- **免費優先**：優先榨乾 Gemini 每日 1,500 次的免費 Request 額度。
- **付費閾值**：除非使用者授權，否則單項任務的付費 API (如 OpenAI) 呼叫量不得超過 **100 題**。
- **餘額監控**：Agent 需定期評估剩餘免費 Request 數 (1500 - 當日已用數)，並在接近 0 時主動提醒使用者。

## 4. 深層驗證 (Deep Verification) — v5.0 標準
- **定義**：不同於純盲測（AI 不看課文），深層驗證會將 R3/R4 研究素材注入 Prompt，讓 AI 以「資深審題專家」身份審查。
- **適用時機**：當 R4 發展綱要完備時，**強制使用**深層驗證取代純盲測。
- **批次策略**：同一課次的題目以 **10 題一組** 發送，最大化語境聚焦效益。
- **效率提升**：相較逐題發送，10-in-1 約可節省 **20-30% Token** 並減少 **80% 請求次數**。
- **品質評級**：每題產生 ⭐1-3 品質評級與 R4 對齊評語，結案報告需包含「平均品質評級」。

## 5. 盲測品質與修正原則
- **推理存證**：盲測不只要結果，更要記錄「AI 的推理理由 (`ai_reasoning`)」。
- **分類複查**：嚴格區分 `distractor_success` (誘答成功) 與 `question_issue` (題目瑕疵)。
- **差異化重寫**：僅針對有瑕疵的題目進行 AI 重寫，嚴禁盲目修改優質誘答。
