# 🌟 V3 Eidos 本質規格書 (v3_design_spec)

**最後修訂時間：** 2026-02-22
**存放路徑：** `apps/v3_eidos/v3_design_spec.md`
**目的：** 定義 Eidos V3 (學生前台介面) 的開發架構，並說明如何與 Lovable 開發的 (`LeoVibe/eidosedu`) 設計稿進行整合對接。

---

## 1. 專案定位與技術棧 (Tech Stack)
*   **定位**：V3 是「理型」的最終呈現，給家長與學生使用的最終複習介面。
*   **前端框架**：基於 Lovable 設計，全面採用 **React 18+** 與 **Vite** 構建。
*   **樣式與組件**：採用 Tailwind CSS + `shadcn/ui` 作為設計語言。
*   **路由機制**：使用 `react-router-dom` 進行 Client-side Routing。

## 2. 與題庫層 (Question Assets) 的整合策略
V3 的核心邏輯是「純視覺層」，本身**不包含任何題庫實體檔案**，而是透過 API 抓取 `eidosProject/question/` 下產生的靜態 JSON。

### 載入路徑對應
Lovable 專案的資料抓取邏輯會依賴 `QUESTION_BASE_URL` 環境變數。
*   **開發環境 (Dev)**：在本地開發時，會在 Vite 的 `public/` 目錄下建立軟連結指向專案的 `question/platform`，使路徑如 `/questions/platform/G3/自然/S1/康軒/manifest.json` 可被存取。
*   **生產環境 (Prod)**：由 Cloudflare Pages 直接吐出靜態 JSON，`QUESTION_BASE_URL` 指向您的發布網域或相同的 Root。

### 頁面路由與資料的 Mapping
V3 前台具備科目的動態路由，例如 `/g3/science/s1/kang_hsuan`，這些參數必須能精緻對應到 `question/api_contract.md` 定義的目錄結構。
> **API 呼叫範例**：  
> URL Match: `/g3/science/s1/kang_hsuan`  
> Fetch Target: `${QUESTION_BASE_URL}/G3/自然/S1/康軒/manifest.json`

## 3. Lovable 整合工作流 (Workflow)
如同總 PM (Antigravity) 規劃，`LeoVibe/eidosedu` Repo 將作為「UI 靈感庫與發布點」，並與 eidosProject「架構邏輯庫」分開管理：

**合作模式分為兩個階段：**
1. **第一階段 (剝離與建構)**：
    * 將 Lovable 專案中的 `src/pages` (前台頁面) 抽出，並依照本文檔的邏輯，將網路請求 (Fetch API) 確實串接至本地的 `question/` 資產。
    * 建立 Mock Data Fallback：當開發者沒有完整題庫時，能透過 Dummy Data 來預覽。
2. **第二階段 (雙向同步機制)**：
    * 當 eidos 架構與邏輯串接完善後，如果 Lovable 專案有新的 UI 更新，我們會針對 `.tsx` 元件檔進行覆蓋。
    * 當 `v3_eidos` 的商業邏輯（如處理答錯的快取記憶體）寫完後，我們將這套邏輯推回（Push）或手動整合至 Lovable 的 Git Repo，實現 UI 與邏輯的完美接合。

---

## 4. 關鍵頁面組件清單 (Components Checklist)
- `Index.tsx`: 首頁導覽 (各科入口)
- `SubjectView.tsx`: 單一科目總覽 (顯示 Manifest 內的章節清單)
- `QuizEngine.tsx`: 答題引擎 (處理由 JSON 讀取出的單題渲染、選項打亂、對錯判定)
- `ResultSummary.tsx`: 結算畫面 (顯示對錯率與詳解)
