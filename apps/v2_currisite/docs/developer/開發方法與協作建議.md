# 開發方法與多 AI 協作建議

本文件整理：**協作方式**、**省 token 做法**、**驗證與同步**，以及**使用者功能改進方向**。  
**AI 角色、改版紀錄、產出與測試的共通原則**請見 **[agent/AI_COLLABORATION_RULES.md](../agent/AI_COLLABORATION_RULES.md)**（可放 global rules）。

---

## 一、開發方法與多 AI 協作

### 1.1 單一契約、避免重複定義

- **問題**：路徑、檔名、JSON 格式若在多次對話或不同文件中重複寫，容易不一致且耗 token。
- **做法**：
  - 題庫與前端對齊規格**只維護一份**：**docs/agent/CONTRACT.md**。
  - Cursor 與 Antigravity 接到任務時，先讀 CONTRACT，再實作或產題庫；回報錯誤時只寫「違反 CONTRACT 第 N 點」或貼路徑/檔名，不重複貼整段規格。

### 1.2 分工邊界寫死在一處

- **Antigravity**：只產出 `public/questions/platform/` 下內容；不改前端。
- **Cursor**：只讀 platform、不寫入；題庫錯誤記入 **record/DATA_ERRORS.md**，不直接改 JSON。
- 上述分工寫在 CONTRACT，兩邊都引用同一份，減少「誰該做什麼」的來回確認。

### 1.3 版本與部署對齊

- 若題庫有「版本」或「產出日」，可在 manifest 或單一 JSON 中加欄位（如 `version`、`generated`），前端可選擇顯示「題庫版本」；雙方以同一版本號溝通，避免「我改了你還沒部署」的落差。
- 部署後由一方（或自動化）跑一次簡單檢查：例如 fetch 數個 manifest + 一個 JSON，確認 200 與格式，再通知對方「已上線、版本 X」。

### 1.4 驗證更簡單

- **Antigravity 交檔前**：依 CONTRACT 檢查清單自檢（路徑、檔名、meta、answer 與 options）。
- **Cursor 接題庫後**：只做「載入 + 一兩個畫面」的 smoke test（例如選 G3 國語 S1 康軒，有題、分課名稱正確）；發現問題記 DATA_ERRORS，不猜規格。
- 若有共用腳本（如驗證 JSON、產生 manifest），放在專案內並在 CONTRACT 或 README 註明指令，兩邊用同一套驗證。

## 二、讓協作更直接、用 token 更少

### 2.1 引用契約而非重貼規格

- 對話中盡量說：「依 CONTRACT 路徑…」「CONTRACT 第 5 點檢查清單第 2 項未過」。
- 需要時只貼**路徑範例**或**單一 JSON 範例**，其餘用「見 CONTRACT」。

### 2.2 路徑／檔名／內容一次定稿

- 新科目或新學期若要新增規則，先在 CONTRACT 增補一節（路徑範例、檔名範例、meta 範例），再各自實作；避免在對話裡零散約定後才補文件。

### 2.3 錯誤回報格式固定

- DATA_ERRORS 用固定區塊：路徑、問題、建議。Antigravity 只需掃該檔即可修正，不需從長對話裡撈脈絡。

### 2.4 文件分類（已做）

- **agent/**：協作契約（CONTRACT）→ 兩邊 AI 只讀這份對齊規格。
- **developer/**：需求與協作方法 → 實作與流程改進用。
- **record/**：錯誤清單、變更紀錄、覆蓋狀況 → 紀錄用，不當規格依賴。

## 三、本站服務功能：後續可擴充與改進方向（使用者角度）

以下以**使用者感受**為主，不綁實作細節。

### 3.1 已具備或已加強

- 進度記憶：上次選擇的年級／學期／出版社已用 localStorage 記憶，下次開啟可恢復。
- 學習統計：「統計」頁已有綜合練習、分類、練習歷史。
- 錯題複習：「錯題」可檢視累積錯題並可再練習。
- 無題庫：改為單一空狀態「題庫建置中」，不再出現多個灰色按鈕。
- 答題回饋：正確/錯誤動畫、解析、即時計數、明顯「下一題」按鈕。
- 分課題數：分課按鈕顯示「(N題)」，方便判斷內容多寡。

### 3.2 可考慮的改進方向

| 方向 | 說明（使用者觀點） |
|------|---------------------|
| **題庫內容** | 每課題數增加（如 5～10 題），由題庫產出方補題。 |
| **統計圖表** | 統計頁增加簡單圖表（如各單元正確率長條圖／折線圖），一眼看出強弱項。 |
| **錯題本** | 錯題可標記「已掌握」或排除，避免重複練到已會的題。 |
| **導覽列** | 小螢幕時出版社／科目改為下拉或分兩行，或收進漢堡選單，減少擁擠。 |
| **練習模式** | 可選「只練錯題」「只練某幾課」或「限時挑戰」。 |
| **無題庫說明** | 空狀態可加「預計完成時間」或「聯絡方式」連結（若題庫方願意提供）。 |

以上可依優先級排入 backlog，與題庫擴充計畫一起規劃。

## 四、小結

- **規格與路徑**：以 **agent/CONTRACT.md** 為單一來源，兩邊引用、不重複貼。
- **分工與錯誤**：CONTRACT 寫死分工；題庫問題只記 **record/DATA_ERRORS.md**。
- **驗證**：各自依 CONTRACT 檢查清單自檢；必要時共用驗證腳本與一次 smoke test。
- **省 token**：少貼長規格、多說「見 CONTRACT / 第 N 點」；錯誤回報用固定格式。
- **功能**：在維持「讀取 platform、唯讀、localStorage」前提下，可逐步加統計圖、錯題本、導覽優化與練習模式，並與題庫擴充同步。
