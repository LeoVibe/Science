## 錯誤的根本原因

### 技術層面

JOB-152 的白名單初始化腳本邏輯：

```
對所有 questions[] 中的每道題：
  設定 blind_evaluation = true
  設定 is_publishable = true
  設定 review_status = "pending_review"
```

這個邏輯在**建立欄位框架**上是正確的，但副作用是：
- **未執行任何實際的盲測驗證**
- 把「欄位存在」等同於「品質通過」
- L7~L12 的占位題（台灣的國球是？ 等）也獲得了 `blind_evaluation=true`

### 判斷層面

JOB-158-Report 的撰寫者看到「549 題全部 blind_evaluation=true」，**未進一步檢查題數分布**，直接得出「國語已完成」的結論。

這是一種**確認偏誤**（confirmation bias）：看到符合預期的數字後，停止了進一步驗證。

## 教訓與防範準則

### 針對白名單初始化類 Job

> 📌 **準則：批量欄位初始化後，必須附帶「題數分布稽核」才算完成。**

驗收任何含「批量初始化」步驟的 Job 時，需額外確認：

```
✅ 各版本各課 題數是否均達標（≥ 目標題數）
✅ blind_evaluation=true 的題目是否來自真實盲測（非批量寫入）
✅ 占位題（題目內容與課程無關）是否已被識別並清除
```

### 針對「題庫完成度」的判定標準

以下條件**同時**滿足，才能聲稱某科目「完成」：

| 條件 | 說明 |
|:--|:--|
| 1. 題數達標 | 各課 ≥ 目標題數（國語：30 題/課） |
| 2. 盲測真實通過 | Match Rate ≥ 85%（來自實際 run_blind_eval.js 執行） |
| 3. 無占位題 | 題目內容與課程主題相關，非測試用 placeholder |
| 4. 欄位一致 | `blind_evaluation` 值與最近一次實際盲測結果吻合 |

### 快速自查指令

在宣告任何科目「完成」前，執行：

```bash
# 1. 確認各課題數
node scripts/evaluate_question_quality.js question/platform/G4/Chinese/S2/[Publisher]

# 2. 確認盲測非批量初始化（查看 blind_eval_results 欄位是否存在）
python3 -c "
import json, glob
for f in glob.glob('question/platform/G4/Chinese/S2/**/*.json', recursive=True):
    d = json.load(open(f))
    qs = d.get('questions', [])
    for q in qs:
        if q.get('blind_evaluation') and not q.get('blind_eval_results'):
            print(f'疑似批量初始化（無真實盲測數據）: {f}')
            break
"
```
