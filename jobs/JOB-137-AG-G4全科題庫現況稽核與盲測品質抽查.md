# JOB-137-AG-G4全科題庫現況稽核與盲測品質抽查

**`job_type`**: `question_verify`
定義與邊界見 **`docs/README_任務派工準則.md`** 第二章。

---

## 📌 任務背景

目前 G4（四年級）題庫的實際完成狀況不明。需要透過真實的檔案查驗，釐清哪些課次已出題、哪些已完成盲測、哪些品質未達標，作為後續補強的依據。

本任務禁止依賴記憶、猜測或舊紀錄文件推斷現況。所有結論必須來自實際讀取檔案內容。

---

## 🎯 任務目標

產出一份 G4 全科題庫現況報告，包含：
1. 各科各課次的出題狀況（有無題目、題數）
2. 各課次的盲測狀況（有無盲測紀錄、Match Rate）
3. 品質抽查結果（每科抽 3-5 題，確認 scenario / explanation / 誘答設計是否實際到位）
4. 優先補強建議清單

---

## 🚧 任務邊界

本次只做：
- G4 全科（國語、數學、自然、社會、英語）現況盤點
- 從實際 JSON 檔案讀取題目與品質欄位
- 從實際盲測紀錄檔案讀取 Match Rate
- 每科抽查 3-5 題進行品質判斷

遇到以下情況，停止並回報，不可自行延伸：
- 發現 JSON 格式異常或欄位缺失 → 記錄在報告，不自行修復
- 發現規範文件有問題 → 記錄在報告，不自行修改
- 抽查題目品質有疑慮但無法判斷 → 標註「需人工複核」，不自行給分

---

## 📖 執行步驟

### 階段一：目錄盤點（不依賴記憶，從檔案系統查）

1. 列出 `question/platform/` 下所有 G4 相關目錄與 JSON 檔案
2. 列出 `knowledge/` 下所有 G4 相關目錄與研究文件
3. 建立 G4 課次清單（科目 × 版本 × 課次）

### 階段二：出題狀況查驗

4. 對每個 G4 JSON 檔案，讀取並記錄：
   - 實際題數
   - 是否存在 `scenario` 欄位（每題都有 vs 部分有 vs 完全沒有）
   - 是否存在 `explanation` 欄位
   - `ql_label` 或品質標籤欄位的實際值

### 階段三：盲測狀況查驗

5. 搜尋 `jobs/` 目錄中與 G4 相關的盲測 Report（含 `question_verify` job_type 或標題含 G4）
6. 從這些 Report 的**實際內容**讀取 Match Rate 數值
7. 判斷標準：
   - 有 Report 且 Match Rate ≥ 85% → 盲測通過
   - 有 Report 但 Match Rate < 85% → 盲測未達標
   - 找不到對應 Report → 未盲測

### 階段四：品質實際抽查

8. 每科從題庫中隨機選取 3-5 題，實際讀取題目內容，逐項判斷：

   | 判斷項目 | 標準 |
   |---|---|
   | `scenario` 是否真實具情境 | 不是只貼課文原文、有實際應用場景 |
   | `explanation` 是否說明解題邏輯 | 不是只寫「答案是A」，要說明為什麼 |
   | 誘答選項是否有設計 | 錯誤選項是常見迷思概念，不是明顯錯誤的湊數選項 |
   | 題幹是否清楚 | 不需要讀兩遍才看懂 |

9. 每道抽查題給出判斷結論：`通過` / `需修正` / `不合格`，並說明理由

### 階段五：彙整報告

10. 產出 `JOB-137-Report.md`，包含：
    - G4 課次完整盤點表（科目 / 版本 / 課次 / 題數 / 有無盲測 / Match Rate / 品質抽查結果）
    - 未出題課次清單
    - 盲測未達標或未盲測課次清單
    - 品質抽查不合格題目清單（含具體原因）
    - 優先補強建議（依嚴重程度排序）
