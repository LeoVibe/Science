## 🔍 前期盤點與問題診斷 (Methodology & Scan)
接獲 JOB-113 任務後，我們透過撰寫第一支客製 Python 腳本 `/tmp/scan_all_questions.py`，列舉了 `question/` 網頁靜態資料夾內所有殘留的 JSON Keys 取樣與檔名正規表示式變異。
**取得以下嚴重災情：**
1. **多重課名變形**：系統內充斥著逾 5 種類別以上的不良命名。如除了正常的 `L1_時間是什麼.json`，在背後同時藏著 `Sci3_昆蟲的一生.json`、`M4_.json`、`Soc1_...` 乃至裸露的 `U1.json`。
2. **屬性位置損壞 (JSON Bloat)**：部分 JSON 檔為變形狀態，將本應處於 `questions` 陣列內部單一題目裡的 `correctAnswer`、`difficulty`、`concept` 擴散到外層的根目錄（如 `apps/v3_eidos/public/question` 早期的殘留廢棄設計），嚴重威脅後續盲審與驗證。
3. **跨層孤島檔案 (Orphans)**：發現於 `Math/S2/` 出現 `HL_NI_Core.json` 等不具備標準 `[Publisher]` 版本依歸的野生檔案。

## ⚙️ 解決方案與大清洗流程 (Data Pipeline Flow)

為了將資料壓縮到單一真理（Single Source of Truth），我們首先更動了專案最高級別的 `question/README_出題與品管準則.md`，加入了「第二章：全站儲存結構與 JSON 字典規範」，強硬規定所有根節點與題目的允許白名單。

隨後我們撰寫了破壞力強大且強制轉化的第二支終極腳本 `/tmp/normalize_questions_v2.py`，以三大流程進行肅清：

### 階段 1：孤島與界外檔案撲殺 (Orphan Execution)
執行 `kill_orphans()` 函式，掃描整個目錄樹的深度。任何沒有深入到 `Publisher` 層級（第四層/第五層），而是停留在 `Grade` 或 `Semester` 目錄的附屬 JSON，均被判定為歷史遺留或系統故障產物，直接調用 `os.remove` 強行剷除。

### 階段 2：無差別提取與屬性標準化 (Schema Enforcement)
當腳本進入 `G*/Subject/S*/Publisher/` 讀取特定 JSON 陣列時：
- **屬性黑名單拋棄**：我們只擷取准許清單的屬性（包含 `taxonomy, question, options, scenario, answer_index...`）。
- **向後相容對齊**：若某題發現舊有的 `correctAnswer` 鍵值，強制將其寫入標準系統的 `answer_index`。其餘所有外掛的野雞屬性（如概念標籤、難易度）全部清除以節省空間與計算成本。

### 階段 3：暴力單元號收斂與題幹去重 (Aggressive Deduplication)
這是最精華的部分：
- **`get_lesson_id` 手段升級**：我們不再信任檔案標頭的英文字母。無論遇到 `Sci1_昆蟲` 還是 `M3_`，腳本唯一的動作就是：**尋找檔名中出現的第一口數字**，並強制賦予其 `L{N}` 的身分代碼。這招徹底打破了因為「英文簡寫名稱不同」造成電腦不願意合併的系統盲點。
- **題幹文字相撞 (Text Hashing)**：被歸入相同 `L{N}`（如 `U1` 與 `Sci1` 都成了 `L1`）的題目池，會再經過嚴格的**空白洗滌與文字比對**，內容 100% 相同的題目將消滅。
- **檔名競選對決**：兩份不同檔名的內容合併時，腳本會統計所有檔名「哪一個中文字長度比較長」，如 `昆蟲的一生` 直接淘汰了純粹名為 `U1` 的無意義檔名。
- **寫入單一神聖產物**：過濾與洗滌過的陣容，最終被整合成唯一的 `L{N}_課名.json` 打入該目錄。並針對原先目錄內不叫這個名字的舊檔案，觸發毀滅指令刪除，終結歷史共業。

### 階段 4：統計更新 (`scripts/rebuild_manifest.py`)
重建網頁目錄並更新到所有追蹤文件，確保前端能顯示 11,768 題的真實進度。

### 階段 5：全域 GUID 化名與 Meta 資訊注射 (The Final Evolution)
為了徹底根絕跨學科或跨版本的檔名混淆（如多處出現 `L4_L4.json`），我們執行了「大重構計畫」：
- **絕對命名標準**：將 651 份檔案全面更名為全域唯一識別碼格式（例：`G6_S2_CHI_HANLIN_L1.json`）。這讓任何一份 JSON 脫離目錄後依然具備完整的身份描述。
- **R3 數據回灌 (Knowledge Injection)**：開發 `extract_r3_metadata.py` 讀取國語科 R3 素材表格，將裡面真實的「中文課名」與「文體主題」反向注入 JSON 的 `meta.title` 與 `meta.theme`。
### 階段 6：Manifest 絕對化與一鍵上架建置 (Phase 6 終章)
為了完全響應全域防呆與日後的自動化部署，我們開發了最終的上架守門員：**`scripts/verify_and_build.js`**。
這支腳本徹底取代了舊有的 manifest 產生器，並賦予了強大的分析與攔截能力：
1. **清理與絕對命名**：自動刪除了全站舊版模稜兩可的 `manifest.json`，並全面動態生成 `G{N}_S{N}_{SUB}_{PUB}_manifest.json`。
2. **品質與盲測盤點**：在生成索引前，腳本會全面掃描所有 `L{N}` 的 CQI 得分、QL 品質標籤，並精準統計有多少題目包含 `blind_evaluation: true` 屬性。
3. **全域統計看板**：統整全站資料並輸出為 `libraryStats.json`。目前（2026-03-26）全站體量來到 **641 份單元檔**，共計 **11,495 題**，其中已有 **1135 題** (覆蓋率約 10%) 通過了 AI 盲測檢核。
