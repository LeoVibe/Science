## 五、各閘門實際 prompt（待使用者審「合理有意義」）

### 階段0 — 考點清單抽取（claude）
```
讀取 knowledge/1_課綱研究/社會/三下/翰林/KL4_三下_翰林_L{N}_考古題與討論.md。
抽出本課「考古考點清單」，每個考點輸出：
- kaodian_id（L{N}-K01…）
- 描述（這個考點在考什麼能力/概念，一句話）
- 來源（對應考古題題號或段落）
只抽真正出現在考古素材中的考點，不得自行擴充。輸出 JSON 陣列。
```

### 階段1 — 契約式出題（codex）
```
你是國小三年級社會科出題老師。依下列「考點清單」為 L{N} 出題，補足到每課≥50。
規則：
1. 每題必須鎖定清單中某一個 kaodian_id，並在欄位 source_kaodian_id 標明。
2. 不得自由發揮考點外的內容。
3. 欄位：scenario（情境題幹）、options（4 選項）、answer_index（0-3）、explanation（解析）。
4. 難度貼近三年級；選項誘答合理；正解位置打散，勿集中。
5. 禁止在選項或解析洩漏答案（不得出現「這也是正解」等後設語）。
考點清單：{階段0 輸出}
```

### 階段3 — 對應 judge（claude sonnet）
```
給定 L{N} 考點清單與一題。判斷此題是否真正對應清單中某個 kaodian_id。
- 對應：題目考核的能力/概念與該考點一致 → 回 {match:true, kaodian_id}
- 不對應：題目偏離所有考點、或自由發揮 → 回 {match:false, reason}
保守判定：模稜兩可一律 match:false。
```

### 階段4 — 文本 judge ＋ 盲測（claude sonnet，雙盲）
```
【盲讀】只給你題幹與 4 選項（不給 answer_index、不給 explanation）。
1. 作答：選出你認為的唯一正解索引。
2. 單一正解：是否只有一個選項成立？若多解或無解，回 single_answer:false。
3. 課別歸屬：題目內容是否屬於「三下社會 翰林 L{N}」的範圍？非本課回 belongs:false。
輸出 {answer_index, single_answer, belongs, reason}。
（系統再比對你的 answer_index 與原 answer_index 是否一致＝Match）
```
