## 三、派工規範 (Assignment Protocol)

### 3.1 命名格式
```
jobs/JOB-{3位數編號}-{英文描述}.md
```
- Cursor 任務：`JOB-001` ~ `JOB-999`
- AG 自行任務：`JOB-AG-001` ~ `JOB-AG-999`

### 3.2 派工單必備欄位
| 區塊 | 內容 |
|------|------|
| **任務背景** | 為什麼要做、解決什麼問題 |
| **任務詳情** | 具體步驟、影響檔案路徑 |
| **關鍵參考檔案** | 開發前必須閱讀的檔案清單（表格形式） |
| **執行規範** | 指向 `.agent/workflows/webdev.md` 或其他 workflow |
| **驗證基準 (DoD)** | 核取清單，明確定義「完成」的標準 |
| **撰寫紀錄** | 必須在文件最上方標註：`*Created by {AG/Cursor} at YYYY-MM-DD HH:mm*` 與 `*Last Updated at YYYY-MM-DD HH:mm ({更新者與事由})*` |

### 3.3 Cursor 指令範本
派工單**不需要**內嵌 Cursor 指令。AG 在對話中直接提供使用者一段**第一人稱**指令：

```
今日任務：{一句話摘要}。
請詳細閱讀並依據 `jobs/JOB-XXX-*.md` 的規格進行開發，
協作規範請遵循 `.agent/workflows/webdev.md`。
完工後請執行單元測試，並將成果與測試紀錄寫入 `jobs/JOB-XXX-Report.md`，
交回給 AG 進行最終測試。
```

## 四、回報規範 (Reporting Protocol)

### 4.1 完工報告
- **路徑**：`jobs/JOB-XXX-Report.md`（與派工單同目錄）
- **命名**：與派工單相同編號，加上 `-Report` 後綴

### 4.2 Report 必備內容
| 區塊 | 說明 |
|------|------|
| **開發成果摘要** | 做了什麼修改、新增了哪些檔案 |
| **變更檔案清單** | 表格列出所有異動檔案與變更類型 |
| **單元測試紀錄** | 測試指令、各測試檔結果、是否全數通過 |
| **PM 驗收建議** | 建議 AG 如何手動驗證（具體步驟） |

### 4.3 禁止事項
- ❌ 嚴禁在根目錄或 `codex/` 產生 `task_assignment_*.md` 等拋棄式回報文件
- ❌ 嚴禁繞過 `jobs/` 目錄自行選擇回報路徑
- ❌ 嚴禁修改不在派工單影響範圍內的檔案（除非提前告知 PM）
- ❌ 嚴禁在**專案根目錄**放置一次性除錯腳本（如 `test.js`、`debug.js`、`tmp_*.js`）。臨時測試檔請放在 `scripts/` 或 `tests/` 目錄下，且完工後必須清除或加入 `.gitignore`，**絕對不可隨正式程式碼一起 commit**
- ❌ **嚴禁未經 PM 許可，自行在專案第一階層（根目錄）建立任何新目錄或隱藏目錄（例如 `.logs/`）**。所有生成的報告或日誌，必須放進既有的 `docs/reports/` 或相關功能目錄下。
- ❌ 嚴禁在程式碼中寫死**個人絕對路徑**（如 `/Users/xxx/...`），必須使用相對路徑或環境變數

## 五、AG 驗收 SOP (Verification Phase)

當使用者回報「Cursor 已完成」時，AG 進入 `VERIFICATION` 模式：

1. **白箱檢查**：讀取 Cursor 新增或修改的原始碼
2. **標準對齊**：確認實作是否完整涵蓋 `JOB-XXX` 定義的所有驗證基準
3. **運行驗證**：若環境允許，執行腳本或啟動 dev server 測試
4. **最終裁定**：
   - ✅ 無誤 → 標記為 `🟢 DONE`，更新本文件任務清單
   - ⚠️ 有瑕疵 → 產生「修正建議清單」，由使用者再次指派

### 6.1 數據就緒狀態
> 數據層由 AG 維護，Cursor 僅需依路徑調用。

| 年級學期 | 狀態 | 備註 |

| G4 S2 (四下) | ✅ 全科目 100% 完備 | 數學、自然已完成 Scaling |
| G3 S2 (三下) | ✅ 全科目 100% 完備 | 含社會 L4+ 題庫 |
| G3~G5 S1 (上學期) | 🔵 部分就緒 | 依 `libraryStats.json` 為準 |

*最終完工驗證：2026-02-24 (AG)*

### 6.2 題目檔格式約定
- 題庫欄位以 `question/題庫API與格式規範.md` 為**單一真相來源**
- 前端支援四種格式 (A / A' / B / C)，詳見 `.agent/workflows/qst_bank.md`
- 新格式上線前，AG 須提供 sample（manifest + 題目檔）讓 Cursor 確認 loader 相容

### 6.3 環境規範
- **符號連結**：`apps/v3_eidos/public/questions` 必須指向根目錄 `question/`
- **Cloudflare**：`wrangler.toml` 須綁定 D1 `eidos-db`、KV `SITE_SETTINGS`、KV `ACTIVITY_LOGS`
- **時間戳記**：所有檔案修改均以 `YYYY-MM-DD HH:mm` 格式標註台北時間
- **Git commit**：應包含任務編號，例如 `feat(api): JOB-001 implemented D1 query`

### 6.4 錯誤回報
若網站出現「尚無題庫」或題目顯示異常，Cursor 記錄於 `docs/DATA_ERRORS.md`，AG 依此在源頭修正。**Cursor 不直接修改 AG 產出的 JSON 資料**。
