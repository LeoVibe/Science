## 一、任務背景與目的

### 問題陳述
現行 CQI (Composite Quality Index) 的四大評分維度（選項對稱性 3.0、情境深度 3.0、認知層次 2.0、結構完整度 2.0）偏重「格式防呆」與「反猜題機制」，尚未涵蓋以下教學核心面向：

| 缺失面向 | 說明 |
| :--- | :--- |
| **易讀性 (Readability)** | 題目用字遣詞是否符合該年級學童的閱讀能力？難度是否超出 Fry Readability 合理範圍？ |
| **認知成熟度匹配 (Cognitive Fit)** | 題目的抽象層次是否符合皮亞傑認知發展階段？低年級是否混入過多邏輯推論？ |
| **課綱對齊度 (Curriculum Alignment)** | 題目是否精準命中學習指標？是否存在「超綱」或「偏離核心」的情形？ |
| **研究方法論達成度 (Research-Backed)** | 題目的迷思設計是否有 R2/R3 階段的考古題或學生錯誤資料作為依據？ |
| **文化公平性 (Cultural Equity)** | 題目情境是否避免城鄉偏見、性別刻板印象？ |
| **鑑別效度 (Discriminative Validity)** | 誘答選項是否能有效區分「真正理解」與「碰巧猜對」的學生？ |

### 研究目標
1. **全面比較**：將現行 CQI 維度與上述缺失面向進行交叉分析。
2. **重構評分表**：設計一套「可量化、可自動化、可操作」的新版品質評分矩陣。
3. **建立追溯規範**：所有文件變更必須記錄「日期時間」與「變更模型」。

## 四、文件變更追溯規範（新規範提案）

### 規範內容
> **所有專案文件（含 MD 文檔、JSON 題庫、研究素材）在每次更新時，必須記錄：**
> 1. **`last_updated`**：更新日期與時間（ISO 格式：`YYYY-MM-DD HH:mm`）
> 2. **`updated_by`**：執行變更的模型或人員名稱（如 `Antigravity-Agent`, `Gemini-2.5-Pro`, `USER`）

### 建議放置位置：`GEMINI.md`（全域高優先設定檔）

**理由分析：**
| 候選位置 | 適合度 | 理由 |
| :--- | :--- | :--- |
| **`~/.gemini/GEMINI.md`** | ⭐⭐⭐⭐⭐ | **最佳選擇**。此檔為全域 User Rules，所有 AI Agent（不分 Gemini/Claude/Antigravity）皆會強制讀取。目前已含版號與日期規範，新增「模型名稱追溯」為邏輯上的自然延伸。 |
| `README.md` (專案根目錄) | ⭐⭐⭐ | 可行，但範圍僅限單一專案，且 README 偏向為人類閱讀。 |
| `_agent/skills/doqst/SKILL.md` | ⭐⭐ | 僅限出題場景，無法涵蓋研究文件與一般文檔。 |
| `docs/` 下的規範文件 | ⭐⭐ | Agent 不一定會主動讀取，缺乏強制性。 |

### 建議的 GEMINI.md 新增條目
```markdown
- **變更追溯**：所有文件（MD、JSON）在創建或修改時，必須在文件頭部或 metadata 中記錄 `last_updated`（日期時間）與 `updated_by`（執行修改的模型或人員名稱），以確保變更歷程有跡可循。
```
