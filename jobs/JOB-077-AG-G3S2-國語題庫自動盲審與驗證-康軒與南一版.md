# JOB-077-AG-G3S2-國語題庫自動盲審與驗證（康軒與南一版）

## 📌 任務背景與歷程迭代
本任務為延續 JOB-076 (翰林版) 的自動盲審，針對小三下學期 (G3S2) 國語題庫的另外兩個主要版本：**康軒 (KangHsuan)** 與 **南一 (NanYi)** 進行全面盲測，確保全站題庫品質。

**【史詩級迭代歷程】**
*   **初期 (v3.0 時代)**：最初設計採「單題單送」模式，因遭遇上下文缺乏導致 AI 對學科深度判斷失準，於本任務初版執行時被迫中斷。
*   **深層驗證 POC (v4.0 時代)**：嘗試直接在 API 請求中注入整份長達 8.5 萬字的 R4 課綱，隨即遭遇 `API MAX_TOKENS` 長度截斷與 API 成本無限膨脹等問題。
*   **效能對決與破冰 (衍生 JOB-078)**：為了解決卡關，創建實驗專案評估五大模型。最終捨棄了舊版的單題模式與不穩定的 OpenAI 解析，挖掘出 `Gemini 3.1 Flash Preview` 打破物理截斷極限的特性。
*   **滿血復工 (v5.0 時代)**：本派工單於 2026/03/22 正式重啟！全面升級主引擎，搭載最新架構與批發模式，進行康軒與南一體的最後掃蕩。

## ⚙️ 系統結構與驗證流程 (v5.0 引擎)
為了克服所有瓶頸，目前系統採取以下三階段精密流程：

1.  **Phase 0: R4 課綱精華萃取 (LLM-RAG)**
    *   **輸入**：自動根據目錄對應讀取完整的 8.5 萬字典藏《發展綱要》(R4)。
    *   **萃取**：利用 LLM 針對當下驗證的課表（如 L1），總結出「課文大意、教學目標、考古題陷阱」等 600 字核心並快取於記憶體。
2.  **Phase 1: 30-in-1 極速批次盲測**
    *   **模型選用**：全線搭載次世代極速模型 **`gemini-3.1-flash-lite-preview`**。
    *   **執行策略**：屏棄單題發送，將 30 題陣列打包成一次 API 請求。此舉大幅減少網路延遲與重複提問造成的 Token 浪費，單檔極速約 5.5 秒。
3.  **Phase 2: 狀態寫回與 Mismatch 追蹤**
    *   精準解構 JSON 陣列，比對 `selected_answer` 與標準答案。
    *   更新實體 JSON 檔案，寫入 `authoring_model`, `verifying_model`, `cqi_score` 以及最新驗證日期。
    *   若發現錯答，則擷取留存 AI 的 `reasoning`，並標記為待複查 `pending` 狀態供日後人工研判。
