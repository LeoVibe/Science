# JOB-281 選項插字清除指令 v2（逐題通讀版，不依賴關鍵字表）

## 背景
本檔案由 `Gemini-2.5-Pro` 出題，其中部分題目（不是全部）的選項文字被插入了不通順、破壞語法的贅字或片語——通常是在句子中間或結尾插入一個與句意無關的名詞（常見如「標記」「標籤」「標識」「標示」「標語」「標誌」「內容」「數據」「數值」「描述」「說明」等），使句子讀起來卡頓、不通順，甚至偶爾重複（如「標記標記」）。

**重要**：這些詞本身都是正常中文詞彙，在合理語境下完全可以自然出現（例如「地圖上的標示」「產品標籤」「時間標記」都是合理內容）。**你不能只靠關鍵字比對**——必須**逐題閱讀 4 個選項的完整句子**，用你的中文語感判斷：這句話讀起來通不通順？是否有一個詞插在句子中間打斷了語法、或掛在句尾顯得多餘？

## 真缺陷 vs 正常用詞範例
**這是缺陷**（贅字打斷語法或無意義地掛在句尾）：
- 「旨在強調必須幸運地擁有魔法般的直覺**標記**，才能在創作過程中無往不利」← 「標記」插在「直覺」和「，才能」中間，讀起來卡頓，去掉後文從句順
- 「深夜努力且不懈實踐...不穩定的瞬間靈感**標識**」（句尾）← 「標識」讀起來像沒說完就多了一個詞
- 「而非單純依靠...瞬間靈感標識」「政變**數據**，藉機奪權」← 「數據」在此語境（政變/奪權）完全不相關，是插入痕跡

**這不是缺陷**（詞彙本身就是句子要表達的內容）：
- 「書店裡有張小小的**標語**，寫著...」← 標語＝故事情節中真實存在的招牌文字
- 「河流、沙洲與山丘**標記**，老師要大家從自然環境找線索」← 標記＝地圖圖例符號，地理課的合理用詞
- 「小明發現貨架上有兩種**標示**」← 標示＝商品上的容量標示，數學題合理情境
- 「作者為了湊字數而加入的**標記**」← 這是一個完整通順、合乎邏輯的錯誤選項（描述音效提示的反諷解讀），不是插字缺陷

## 鐵律
1. **逐題讀完整句子**，判斷每個選項是否通順。不通順的才動；通順的（即使含上述關鍵字）絕對不要碰。
2. **只刪除造成不通順的贅字/片語**，不改其他文字。句子其餘部分、標點、語意、長度盡量保留原樣（只做刪除贅字後必要的最小標點調整）。
3. **不改 `answer_index`**、不改正解語意。
4. **不改其他欄位**（scenario/explanation 若也有同類贅字，一併比照同一標準判斷並清除；但題幹通常不需要動，除非贅字確實在題幹裡）。
5. 清除後若造成正解變成該課「唯一最長選項」比例過高（>40%），對誘答做最小幅度加長（只加長誘答不改正解），維持 BIAS ≤40%。

## 執行步驟
1. 讀你分到的整份題庫檔（`question/platform/.../G5_S2_CHI_....json`），**逐題逐選項閱讀**
2. 列出你判斷為「贅字缺陷」的題目與具體位置
3. 用 python 手術式修改（`json.dump(d, f, ensure_ascii=False, indent=2)`，2 空格縮排），只動確認有缺陷的選項/題幹文字
4. 自我驗證：
   - 題數不變、未修改題目 byte-identical
   - 所有 answer_index 與修改前完全相同
   - 重讀一遍你改過的句子，確認通順、意思沒變
   - 重算全課 BIAS（正解嚴格唯一最長比例）≤40%
5. 產出 `jobs/_goal-work/JOB281/recast/<檔名>.recast.json`：
   `[{"index":N, "field":"options|question|scenario", "old":"...", "new":"...", "reason":"一句話說明為何判定為缺陷"}]`
6. **禁止**呼叫 `evaluate_question_quality.js` / `generate_library_stats.js`（全站寫回副作用）。
