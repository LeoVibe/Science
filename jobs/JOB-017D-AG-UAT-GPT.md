## 二、 角色設定與測試劇本 (UAT Personas & Playbooks)

請執行以下三個主要劇本，找出系統潛在的問題：

### 🎭 劇本 A：迷航的三年級學生 (User Journey)
1. **冷啟動體驗**：首次進入根路徑 `/`，預設年級是否正確加載？
2. **極限切換**：連續切換 國語 -> 數學 -> 自然，URL router 是否 100% 同步且沒有殘留上一個科目的 UI 顏色？題庫總覽顯示的數字是否正確濾除？
3. **答題中斷與續答**：寫進階挑戰到一半 -> **強制 F5 重新整理頁面** -> 進度是否還原或優雅清除？故意選擇一個「無題庫」的單元，系統是否給予明確的 Empty State？
4. **成就清除驗證**：進到設定頁 -> 按下「清除紀錄」 -> 統計是否真的歸零？

### 🎭 劇本 B：嚴格的題庫品管員 (Data Edge Cases)
1. **JSON 容錯測試**：前端 `questionLoader` 遇到空陣列、缺少 `options` 或 `answer_index` 越界時的 Error Boundary 是否健全？
2. **路由深連結 (Deep Linking)**：直接把網址改成深層路徑（如錯題本）然後貼在無痕視窗開啟，題庫能否在跨組件初始化時正確還原當下狀態？

### 🎭 劇本 C：手忙腳亂的後台 Owner (Admin Panel)
1. **權限攔截**：直接在瀏覽器輸入 `/admin/system/users` 是否被正確攔截或導向登入頁？
2. **Library Manager 開關效力**：在管理介面關閉題庫，在前台切換到該組合時，系統是否會阻止進入或正確隱藏？
3. **資料庫同步**：更改設定後，`localStorage` 中的 `EIDOS_LIBRARY_CONFIG` 與 `APP_CONFIG` 的交集邏輯是否正確？

## 三、 產出格式要求：上線診斷報告 (Diagnostic Report)

請將測試結果寫入 `jobs/JOB-017D-Report.md`，內容必須包含以下結構：

1. **問題清單 (Issue Log)**
   將發現的問題或隱患，強制歸類至以下四種類型之一：
   - 💻 **系統架構面 (System)**：如 State 殘留、路由閃爍、深層連結失敗、Error Boundary 失效。
   - 🛠️ **前端技術面 (Tech)**：如 CSS Tailwind 覆蓋失敗、API Fetch 例外未處理。
   - 👦 **操作體驗面 (UX)**：針對小學生不夠直覺的防呆、引導文字太生硬、畫面切換突兀。
   - 📚 **題庫資料面 (Data)**：品質閘門卡死、選項渲染異常。

2. **嚴重性分級 (Severity)**
   - 🟥 **Critical (致命)**：Crash、白畫面、點了沒反應。
   - 🟧 **High (高)**：功能邏輯錯誤（如關閉題庫還能玩）、嚴重跳板。
   - 🟨 **Medium (中)**：樣式跑版、小流程不順。
   - 🟩 **Low (低)**：文字建議、提示訊息加強。

3. **專家解答 (Proposed Solution)**
   請針對每一項列出的問題，給出**具體程式碼層級的修改建議或架構重構策略**。
