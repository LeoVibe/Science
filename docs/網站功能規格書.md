## 一、全域設計系統

### 1.1 設計主題：溫暖琥珀 (Warm Amber)

靈感來源：Notion × Apple Books — 溫潤書卷感  
目標受眾：國小學生，需友善、不疲勞的閱讀體驗

| 角色 | CSS 變數 | HSL 值 | 說明 |
|------|----------|--------|------|
| 背景 | `--background` | `40 30% 97%` | 暖象牙白 |
| 前景文字 | `--foreground` | `30 12% 20%` | 溫暖深棕 |
| 主色 | `--primary` | `38 65% 50%` | 琥珀金 |
| 強調色 | `--accent` | `22 60% 56%` | 暖橘 |
| 卡片背景 | `--card` | `40 20% 99%` | 近白暖色 |
| 邊框 | `--border` | `35 12% 88%` | 淡暖灰 |

### 1.2 科目色彩

每個科目有獨立的主色與淺色背景，透過 CSS 變數 `--subject-{theme}` 統一管理：

| 科目 | theme key | 主色 HSL | Icon |
|------|-----------|----------|------|
| 國語 | `chinese` | `345 42% 62%`（玫瑰粉） | 📖 |
| 數學 | `math` | `200 45% 55%`（天空藍） | ➕ |
| 英語 | `english` | `8 50% 60%`（珊瑚紅） | 🅰️ |
| 自然 | `science` | `165 35% 50%`（湖水綠） | 🔬 |
| 社會 | `social` | `85 35% 50%`（橄欖綠） | 🏛️ |
| 生活 | `life` | `275 32% 62%`（薰衣草紫） | 🌈 |

> **設計決策**：英語與社會的顏色刻意遠離主色琥珀的色相（38°），避免視覺混淆。

### 1.3 出版社色彩

| 出版社 | 色彩 | 色碼 |
|--------|------|------|
| 康軒 | 寧靜藍 | `hsl(200 55% 55%)` |
| 南一 | 柔和粉玫瑰 | `hsl(350 50% 65%)` |
| 翰林 | 清新湖水綠 | `hsl(168 45% 50%)` |

### 1.4 字型

- **主字型**：Nunito（Google Fonts），`wght@400;600;700;800;900`
- **標題**：`font-bold` 或 `font-black`
- **輔助文字**：`font-medium text-muted-foreground`

### 1.5 圓角與陰影

- 大卡片：`rounded-3xl`（主內容區）或 `rounded-2xl`（按鈕、子卡片）
- 小標籤/pill：`rounded-full`
- 懸浮互動：`shadow-sm hover:shadow-md transition-all`
- 靜態卡片：`border border-border/50` + `bg-card`

## 二、元件規格

### 2.1 年級選擇器（AppHeader 左上）

**琥珀盾牌 SVG 徽章**：
- 盾牌底色：`hsl(38 80% 52%)`
- 年級大字（白色粗體 16px）偏左上，學期小字（白色 10px）偏右下
- 點擊觸發「學習與使用設定」modal
- hover 時：`drop-shadow-md`

### 2.2 科目導覽 Pills（AppHeader）

- 與年級選擇器之間有 **灰色分隔線** (`w-px h-6 bg-border/60`)
- 間距：`gap-2`
- Active 狀態：科目主色填滿 `+ white text`
- Inactive 狀態：`bg-secondary text-secondary-foreground`

### 2.3 挑戰按鈕（MainMenu）

**左右並排** (`grid grid-cols-2 gap-3`)，兩行置中排列：

| | 基本挑戰 | 進階挑戰 |
|--|---------|---------|
| **第一行** | 🎯 基本挑戰 `[10題]` | ⭐ 進階挑戰 `[25題]` |
| **第二行** | 隨機出題・快速複習 | 深度練習・全面檢測 |
| **底色** | 白底 (`bg-card`) | 科目漸層 (`gradient-{theme}`) |
| **邊框** | 科目色 40% 透明度 | 無 |
| **文字色** | 科目色 | 白色 |
| **題數 pill** | 科目色文字 + 科目色 10% 底 | `bg-white/20` |
| **padding** | `py-2.5 px-3` | `py-2.5 px-3` |

> **設計決策**：進階挑戰底色與基本挑戰文字/邊框均**跟隨科目色**動態變化，使不同科目有視覺個性。

### 2.4 分課按鈕（MainMenu）

- **白卡底**：`bg-white border border-gray-100`
- **左側色條**：`absolute left-0 top-0 bottom-0 w-1 rounded-l-2xl`，顏色 = 科目色
- **文字**：`pl-2 text-gray-700 leading-snug`
- **圓角**：`rounded-2xl`
- **互動**：`shadow-sm hover:shadow-md active:scale-[0.98]`

### 2.5 題目卡（QuizView）

**頂部標籤列**（同一行排列）：
```
[課文名 pill]  📌 情境說明文字               選擇題
```
- 課文名：科目色 pill (`subject-bg-{theme}-light subject-text-{theme}`)
- 情境說明：`text-xs text-muted-foreground`，與課文名同行（不另起一行）
- 「選擇題」：`text-[10px]` + `ml-auto` 推到最右側

### 2.6 學習與使用設定 Modal（ProfileSetup）

**分頁**：
1. 🎒 學科、出版社設定
2. ⚡️ 操作習慣

**「操作習慣」分頁內容**：
- 答題後自動下一題延遲（0/1/1.5/2/3 秒）
- A–D 快捷鍵開關
- 進階挑戰題目數量（10/15/20/25/30）
- 🗑️ 清除學習紀錄（按科目逐一清除）

**清除學習紀錄規格**：
- 僅清除當前年級的 localStorage 紀錄
- 可選擇哪一科要清空
- 後台 API 統計**持續累計不受影響**
- 需 `confirm()` 二次確認

## 三、頁面行為規格

### 3.1 路由與導航

| 規則 | 說明 |
|------|------|
| 根路徑 `/` 行為 | **不自動跳轉**至深層路徑，保持根路徑 |
| URL 同步時機 | 使用者主動切換科目/年級後才 navigate |
| URL 格式 | `/:grade/:subject/:semester/:publisher/:view?/:subTab?` |
| 懶載入觸發 | view 為 `quiz`/`review`/`result`/`wrong-questions` 時載入完整題庫 |
| 深連結防呆 | `quiz` / `result` / `wrong-questions` 若缺少 session state，必須自動回退 `menu`，不得白畫面 |

### 3.2 題庫與品質總覽

- **只顯示使用者當前設定的年級和學期**，不遍歷所有年級
- 資料來源：`libraryStats.json`

### 3.3 累積錯題本

- 從 `loaded.questions` 的 `questionMap` 查找題目文字
- 若找不到應顯示題目全文（非 ID）
- 需確保 `needFull` 包含 `result` 和 `wrong-questions` view

### 3.4 維護模式

- `SITE_STATUS === 'Maintenance'` 時自動導向 `/maintenance`
- 由 `MaintenanceGuard` 元件控制
- 全域 Render 例外須由 `ErrorBoundary` 捕捉並提供可恢復 UI（重新整理按鈕）

## 四、資料儲存規格

### 4.1 localStorage Keys

| Key 格式 | 說明 |
|----------|------|
| `history_G{n}_{SUBJ}_S{n}_{PUB}` | 答題歷程（每題正確/錯誤次數） |
| `progress_G{n}_{SUBJ}_S{n}_{PUB}` | 答題進度（斷點續答，24h 過期） |
| `sci_v2_all_practice_history` | 所有練習紀錄（上限 200 筆） |
| `sci_v2_user_profile` | 使用者設定（年級/學期/出版社/偏好） |
| `sci_v2_user_preference` | 舊版偏好（向後相容） |
| `eidos_user_id` | 匿名使用者 ID（UUID） |
| `EIDOS_LIBRARY_CONFIG` | 題庫啟用設定（從 admin 同步） |

> 啟動時設定來源優先順序：`Cloudflare /api/settings`（含 default_* 與 `library_config`） > `sci_v2_user_profile` > `sci_v2_user_preference`。

### 4.2 清除機制

- `clearSubjectHistory(grade, subject, semester, publisher)`：清除指定科目的 history + progress + practice
- `clearAllHistory(includeProfileData?)`：清除所有 `history_*`、`progress_*` 和 practice；若 `includeProfileData=true`，一併清除 `eidos_user_id`、`sci_v2_user_profile`、`sci_v2_user_preference`

### 4.3 答題進度續答

- `QuizView` 每次確認答案後，必須更新 `progress_G{n}_{SUBJ}_S{n}_{PUB}`。
- 啟動測驗時若有未逾期進度（24 小時內），需詢問使用者是否續答。

## § 維護機制

### 目的

確保此規格書隨開發持續更新、不與實作矛盾。

### 三種維護時機

#### 1️⃣ 派工單完成後（每張單）

當一張派工單涉及以下任一項目時，**AI 必須同步更新本文件**：
- 新增 / 修改 UI 元件的排列、配色或互動行為
- 修改路由邏輯或頁面行為
- 新增 / 修改 localStorage key 或資料結構
- 修改設定面板的選項

**更新方式**：在 walkthrough 結尾附上「規格書同步」區塊，列出修改了哪些章節。

#### 2️⃣ 衝突解決（發現矛盾時）

當新的派工指令與本文件記載的規格**矛盾**時：
1. AI 應**主動提醒**使用者存在矛盾
2. 確認以「最新指令」為準後，直接**覆寫**本文件中的舊規格
3. 在更新紀錄中註明「覆蓋原因」

#### 3️⃣ 定期總檢（建議每月 1 次）

使用以下 prompt 啟動全檔掃描：
```
請對照目前的程式碼，檢查 docs/網站功能規格書.md 中是否有與實際實作不符的內容，
列出差異並更新規格書。
```
