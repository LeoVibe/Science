### 1.1 設計主題：溫暖琥珀 (Warm Amber)

靈感來源：Notion × Apple Books — 溫潤書卷感

### 1.4 字型

- **主字型（body）**：Nunito（Google Fonts），`wght@400;600;700;800;900`，搭配 Noto Sans TC 處理正體中文字
- **標題字型（`h1`/`h2`/`.font-zh`）**：Iansui（手寫正體中文）→ Noto Sans TC fallback；`letter-spacing: 0.02em`。JOB-204 起試行，目的為標題更溫暖有童趣、支援注音符號。
- **數字字型（`.num` class）**：Baloo 2（英文/數字圓潤活潑）→ ui-monospace fallback；`font-variant-numeric: tabular-nums` 確保位數對齊。JOB-204 起套用於題數、分數、正確率、練習統計等位置。
- **標題字重**：`font-bold` 或 `font-black`
- **輔助文字**：`font-medium text-muted-foreground`

**載入來源**（`apps/v3_eidos/index.html`）：
```html
<link href="https://fonts.googleapis.com/css2?family=Noto+Sans+TC:wght@400;500;700;900&family=Baloo+2:wght@500;700&family=Iansui&display=swap" rel="stylesheet">
```

**退版**：若 Iansui / Baloo 2 使用效果不佳，`git revert JOB-204 commit` 即完全恢復原 Nunito 單字型配置。

### 1.5 圓角與陰影

- 大卡片：`rounded-3xl`（主內容區）或 `rounded-2xl`（按鈕、子卡片）
- 小標籤/pill：`rounded-full`
- 懸浮互動：`shadow-sm hover:shadow-md transition-all`
- 靜態卡片：`border border-border/50` + `bg-card`

## 二、元件規格

### 2.1 年級選擇器（AppHeader 左上）

**琥珀盾牌 SVG 徽章**：
- 盾牌底色：`hsl(38 80% 52%)`
- 年級大字（白色粗體 16px）偏左上，學期小字（白色 10px）偏右下
- 點擊觸發「學習與使用設定」modal
- hover 時：`drop-shadow-md`

### 2.2 科目導覽 Pills（AppHeader）

- 與年級選擇器之間有 **灰色分隔線** (`w-px h-6 bg-border/60`)
- 間距：`gap-2`
- Active 狀態：科目主色填滿 `+ white text`
- Inactive 狀態：`bg-secondary text-secondary-foreground`
- **停用科目（JOB-256）**：`data/config.ts` 的 `DISABLED_SUBJECTS`（目前＝數學、英語）為選單與路由的單一真相。`getSubjectsByGrade` 以 `isSubjectEnabled` 過濾，停用科目不顯示於 Pills；`Index.tsx` 三道防線（兩個 URL 解析 effect + 未開放科目自動切換）攔截 `/{g}/mat|eng/...` 深連結。恢復上架只需從清單移除該科目。

### 2.2.1 BETA 標記（JOB-256）

- **上架兩級對應**：QL4＝正式（無標記）、QL3＝BETA（標「尚未嚴謹測試」）、QL2 以下不上架。
- 進入 menu／quiz 時，若當前題庫品質未達 QL4（`utils/libraryAvailability.ts` 的 `isBetaLibrary`，依 `libraryStats.publisherStats[key].quality`），於內容區頂部置中顯示「BETA」膠囊標記（amber 系，`text-[10px] tracking-widest rounded-full`）。
- 判定來源為 `libraryStats`，故須在 `generate_library_stats.js` 重生成後才反映最新 QL。

### 2.3 挑戰按鈕（MainMenu）

**綜合練習標題**：可顯示「（總計 X 題）」，X 為當前科目/出版者題庫總數，來自 `loaded.questions.length`。

**左右並排** (`grid grid-cols-2 gap-3`)，兩行置中排列；按鈕字級以 `text-base` 為主、副標 `text-xs`，RWD 使用 `min-w-0`、`flex-wrap` 避免溢出：

| | 基本挑戰 | 進階挑戰 |
|--|---------|---------|
| **第一行** | 🎯 基本挑戰 `[10題]` | ⭐ 進階挑戰 `[N題]`（N = User Profile 進階題數，10～50） |
| **第二行** | 隨機出題・快速複習 | 深度練習・全面檢測 |
| **底色** | 白底 (`bg-card`) | 科目漸層 (`gradient-{theme}`) |
| **邊框** | 科目色 40% 透明度 | 無 |
| **文字色** | 科目色 | 白色 |
| **題數 pill** | 科目色文字 + 科目色 10% 底 | `bg-white/20` |
| **padding** | `py-3 px-3` | `py-3 px-3` |

進階挑戰題數由 `UserProfile.maxQuizQuestions`（storage）提供，與「學習與使用設定」內「進階挑戰題目數量」同步。

> **設計決策**：進階挑戰底色與基本挑戰文字/邊框均**跟隨科目色**動態變化，使不同科目有視覺個性。

**分頁**：

2. ⚡️ 操作習慣

### 2.7 研究深探（AboutView 分頁）

- **入口**：關於頁分頁列「🔬 研究深探」，路由為 `about/deepdive`。
- **內容**：長篇文章閱讀，首波為兩篇固定文章（智慧抽題、小三黃金複習期），以 JSX 結構渲染。
- **互動**：每篇文章下方「👍 這篇對我有幫助」點讚（計數存於 `EIDOS_DEEPDIVE_LIKES`）、「家長留言／提問」表單與列表（存於 `EIDOS_DEEPDIVE_COMMENTS`）；目前為本機儲存，預留日後串接後端。

### 2.8 教育價值導覽元件（Overlay）

- **OnboardingModal**：首次進入主選單時顯示（依 `hasSeenValueOnboarding` 防擾民）。內容為「皮亞傑的具體運算期」「大腦友善設計」科普卡片；按鈕「👉 了解更多我們的腦科學研究」導向研究深探分頁，「稍後再說」僅關閉並寫入已讀。使用 `bg-card`、`border-border`、`text-foreground`/`text-muted-foreground`，無 hardcode 色碼。
- **InsightDrawer**：主選單「分課練習」旁 💡 按鈕觸發，自右側滑出抽屜，說明認知配比 4-4-2；須有明顯關閉 (✕) 與 Esc 關閉，RWD 下不崩版（`max-w-sm`、全寬側欄）。
- **IntentionTooltip**：在答題解析（explanation）旁顯示 ? 圖示，hover 顯示設計意圖氣泡（如「本題解析說明設計意圖與誘答巧思…」）；掛載於 QuizView、ResultView、ReviewView、WrongQuestionsView、LearningReportView。使用既有 `@/components/ui/tooltip` 與語意色。

### 2.9 首登引導行為 (Welcome Setup)

**觸發時機**：LocalStorage 偵測到無 `UserProfile` 或 `setupComplete !== true` 時，全螢幕鎖定顯示。

- **智慧學期判定**：根據系統月份自動預設學期（2-8月為下學期，9-1月為上學期）。
- **年級與科目連動**：年級選擇按鈕與 `libraryConfig` 同步，動態顯示開放狀態；若該年級無題庫則呈現 `disabled` 狀態。
- **UI/UX 指引**：
    - 使用手指游標 (👆) 置於上方直接指向盾牌圖示，引導使用者未來可於左上角修改設定。
    - 出版社設定預設展開，但標註為「選填（若不清楚可先略過）」，系統會隨機指派版本以確保留存感。
- **理念傳達**：
    - 底部包含「4-4-2 黃金複習心法」說明與開發者感性初衷。
    - 移除早期零碎彈窗，整合為單一流程。

## 三、頁面行為規格

### 3.1 路由與導航

| 規則 | 說明 |
|------|------|
| 根路徑 `/` 行為 | **不自動跳轉**至深層路徑，保持根路徑 |
| URL 同步時機 | 使用者主動切換科目/年級後才 navigate |
| URL 格式 | `/:grade/:subject/:semester/:publisher/:view?/:subTab?` |
| 懶載入觸發 | view 為 `quiz`/`review`/`result`/`wrong-questions` 時載入完整題庫 |
| 深連結防呆 | `quiz` / `result` / `wrong-questions` 若缺少 session state，必須自動回退 `menu`，不得白畫面 |

### 3.2 題庫與品質總覽

- **跨年級全視角**：打破單一年級限制，遍歷所有有效年級（G3-G5）顯示統計總表。
- **動態過濾**：自動隱藏 `libraryConfig` 中被禁用的科目，確保 UI 與 API 資源 1:1 對齊。
- **可用題庫門檻**：前台以 `libraryStats.publisherStats` 的上架題數門檻（`publishedQuestions`，無則回退 `questions`）與 `units` 判斷題庫是否可用；若 URL 指定組合未達門檻，會自動切換到第一個可用科目並提示。
- **品質等級計算**：
    - QL 完整定義見 `question/README_驗證與盲測準則.md` 第四章
    - 每科公式：某題庫中達 QL_X 以上等級的題目比例 ≥ 90% → 該題庫 = QL_X（取最高達標）
    - `libraryStats.publisherStats` 新增 `qlCounts`、`ql4pct`、`ql3pct` 欄位供升級分析
- **資料指標**：
    - 顯示 QL1-QL4 品質等級標籤。
    - 顯示各科目、各出版者的總題數與單元數。
- **題數計算**：當 manifest 單元缺少有效 `count`（或 count <= 0）時，題數以已載入題目的類別/標題加總推導，避免顯示 0 題。
- **入口對接**：點擊表格中的「X 題」連結，可直接跳轉至該科目的審閱模式 (ReviewView)。
- **資料來源**：`libraryStats.json`。

### 3.3 累積錯題本

- 從 `loaded.questions` 的 `questionMap` 查找題目文字
- 若找不到應顯示題目全文（非 ID）
- 需確保 `needFull` 包含 `result` 和 `wrong-questions` view

### 3.4 維護模式

- `SITE_STATUS === 'Maintenance'` 時自動導向 `/maintenance`
- 由 `MaintenanceGuard` 元件控制
- 全域 Render 例外須由 `ErrorBoundary` 捕捉並提供可恢復 UI（重新整理按鈕）

### 3.5 更版資訊（About / Changelog）

- 更版資訊需以「使用者有感」為主，不記錄情緒化描述或內部測試語句。
- 版本敘事採明確節點：`0.7`（介面重整）→ `0.8`（穩定性）→ `0.9`（後台治理）→ `1.0`（正式版）。
- `1.0` 為正式版定位，需標示為當前主版本。
- 歷史版連結（`/history/v0.1/`、`/history/v0.5/`）可保留，但文案需明示「歷史相容版」。

### 3.6 歷史版相容模式（v0.1 / v0.5）

- 保留原歷史網址：`/history/v0.1/`、`/history/v0.5/`。
- 歷史版本主入口：`/history/v1_science/`、`/history/v2_currisite/`，分別載入 v0.1 / v0.5 的既有 bundle。
- `v1_science` / `v2_currisite` 入口的 JS/CSS 路徑需使用相對路徑（`../v0.x/assets/...`），避免 GitHub Pages 子路徑部署失效。
- `v0.1` / `v0.5` 相容橋接頁需使用相對跳轉（`../../?legacy=...`），避免從 `/Science/` 跳到網域根目錄。
- 不重建舊版 bundle，不新增平行題庫 schema，維持與現行 `question/platform` 相容。
- 導向頁需保留手動連結，避免瀏覽器阻擋自動跳轉時無法操作。

## 四、資料儲存規格

### 4.1 localStorage Keys

| Key 格式 | 說明 |
|----------|------|
| `history_G{n}_{SUBJ}_S{n}_{PUB}` | 答題歷程（每題正確/錯誤次數） |
| `progress_G{n}_{SUBJ}_S{n}_{PUB}` | 答題進度（斷點續答，24h 過期） |
| `sci_v2_all_practice_history` | 所有練習紀錄（上限 200 筆） |
| `sci_v2_user_profile` | 使用者設定（年級/學期/出版社/偏好） |
| `sci_v2_user_preference` | 舊版偏好（向後相容） |
| `eidos_user_id` | 匿名使用者 ID（UUID） |
| `EIDOS_LIBRARY_CONFIG` | 題庫啟用設定（從 admin 同步） |
| `hasSeenValueOnboarding` | 是否已看過教育價值導覽 Modal（`true` 後不再彈出） |
| `EIDOS_DEEPDIVE_LIKES` | 研究深探文章點讚計數（JSON：articleId → count） |
| `EIDOS_DEEPDIVE_COMMENTS` | 研究深探家長留言（JSON 陣列，含 articleId、text、timestamp） |

> 啟動時設定來源優先順序：`Cloudflare /api/settings`（含 default_* 與 `library_config`） > `sci_v2_user_profile` > `sci_v2_user_preference`。  
> `sci_v2_user_profile` 內含 `maxQuizQuestions`（進階挑戰題數，預設 25），與 MainMenu 進階按鈕題數同步。

### 4.2 清除機制

- `clearSubjectHistory(grade, subject, semester, publisher)`：清除指定科目的 history + progress + practice
- `clearAllHistory(includeProfileData?)`：清除所有 `history_*`、`progress_*` 和 practice；若 `includeProfileData=true`，一併清除 `eidos_user_id`、`sci_v2_user_profile`、`sci_v2_user_preference`

### 4.3 答題進度續答

- `QuizView` 每次確認答案後，必須更新 `progress_G{n}_{SUBJ}_S{n}_{PUB}`。
- 啟動測驗時若有未逾期進度（24 小時內），需詢問使用者是否續答。

### 6.1 測試檔案

| 檔案 | 覆蓋範圍 |

| `tests/history-subpath.spec.ts` | 歷史入口與相容橋接路徑非 404 |

### 6.2 Playwright 設定

- `baseURL`：`http://localhost:8080`
- Web Server：自動啟動 `npm run dev`
- Browser：Chromium + Firefox

### 6.3 GitHub Pages 子路徑部署驗證 SOP

每次部署後必須人工驗證以下 URL（以正式站為例）：

1. `https://exam15.pages.dev/`
2. `https://exam15.pages.dev/history/v1_science/`
3. `https://exam15.pages.dev/history/v2_currisite/`
4. 至少一條 manifest URL（例如：`https://exam15.pages.dev/question/platform/G5/Chinese/S2/HanLin/G5_S2_CHI_HANLIN_manifest.json`）

驗證結果標準：
- 不能出現 GitHub Pages 404 或 App NotFound 畫面。
- `history/v1_science`、`history/v2_currisite` 需可載入頁面主內容。
- manifest 需回應 200 且可解析為 JSON。

## § 維護機制

### 目的

確保此規格書隨開發持續更新、不與實作矛盾。

### 三種維護時機

#### 1️⃣ 派工單完成後（每張單）

當一張派工單涉及以下任一項目時，**AI 必須同步更新本文件**：
- 新增 / 修改 UI 元件的排列、配色或互動行為
- 修改路由邏輯或頁面行為
- 新增 / 修改 localStorage key 或資料結構
- 修改設定面板的選項

**更新方式**：在 walkthrough 結尾附上「規格書同步」區塊，列出修改了哪些章節。

#### 2️⃣ 衝突解決（發現矛盾時）

當新的派工指令與本文件記載的規格**矛盾**時：
1. AI 應**主動提醒**使用者存在矛盾
2. 確認以「最新指令」為準後，直接**覆寫**本文件中的舊規格
3. 在更新紀錄中註明「覆蓋原因」

#### 3️⃣ 定期總檢（建議每月 1 次）

使用以下 prompt 啟動全檔掃描：
```
請對照目前的程式碼，檢查 docs/網站功能規格書.md 中是否有與實際實作不符的內容，
列出差異並更新規格書。
```
