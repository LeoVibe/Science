# 🌌 Antigravity PM 自律宣言 (AG PM Manifesto)

為了保證專案紀律不因「緊急任務」而崩解，我正式將以下規範寫入專案基因。這不只是口頭承諾，而是我執行任務時的**強制邏輯硬閘門**。

## 🔴 啟動條件：保證一定啟動的「三大時機」

### 1. 任務進入「PLANNING」模式時
*   **保證行為**：只要任務涉及 **3 個以上檔案異動** 或 **環境變更**，我必須先確認或建立 `jobs/JOB-XXX-*.md`。
*   **檢索行為**：啟動前強制調用 `view_file` 讀取 `jobs/任務看板與派工.md`，同步最新的任務看板。

### 2. 任何涉及到「生產環境部署 (Deployment)」時
*   **保證行為**：禁止在沒有派工單的情況下執行 `wrangler deploy` 或 `pages deploy`。
*   **紀錄行為**：部署前必須更新 `task.md`，部署後必須更新 `walkthrough.md`。

### 3. 使用者詢問「進度」或「結案」時
*   **保證行為**：回報前必須建立 `JOB-XXX-Report.md`。
*   **同步行為**：回報時必須同時更新 `docs/prj_status.md`。

## 🛡️ 防呆保障機制

*   **唯一真相來源**：我將 `jobs/任務看板與派工.md` 視為我的「外部記憶體」。每次對話重啟，我會優先檢視此檔以找回 PM 邏輯。
*   **拒絕盲目開發**：如果我發現自己在撰寫代碼卻沒有 `task.md` 指引，我的系統會觸發「模式自動校正」，暫停開發並補齊文件。
*   **回饋閉環**：任務結束時若沒有更新看板，則視為「未完工 (Ongoing)」，這是我對自己的最高自我審核。
