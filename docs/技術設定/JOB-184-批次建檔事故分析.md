## 三、根因：三層防線同時崩壞

### 層 1：產題腳本 fallback 設計缺陷

三支腳本都有「找不到課名時 silent fallback 到 id」的 pattern：

```javascript
// scripts/repair_manifests.js:63（修復前）
title: content.lesson_title || content.category || id,    // ← fallback 到 id (L1/L2/...)

// scripts/auto_generate_questions.js:80（修復前）
title: m.title || jsonObj.lesson_title,                    // ← 缺值時 undefined

// scripts/job184_g5s2_social_orchestrator.js:147（修復前）
title: meta.title || lessonId,                             // ← fallback 到 lessonId
```

**問題**：沒有任何一支腳本在課名缺失時**停下來報錯要求人工介入**，產生 silent corruption。

### 層 2：commit 紀律崩壞

`eccb974` 是**歷史最大單一 commit** 之一，含 5-6 個 JOB 的累積未 commit 產物：

```
scripts/job167_phase3_apply.js
scripts/job169/build_job169_banks.mjs
scripts/job169_regen_g4s2_sci_nan_yi.js
scripts/job171_*.js
scripts/job182_prune_g5s2_chinese_by_kl4.js
scripts/job183_merge_g5_chinese_s2.js
scripts/job184_g5s2_social_orchestrator.js
scripts/patch_kl4_s2_platform_gaps.js
```

**問題**：
- commit message **只提 JOB-184**，完全隱藏其他 5 個 JOB 的變更
- JOB-184 Report 只自述改動 G5 社會 16 課，從未提及順便建的 101 個其他 manifest
- 沒有任何紀律工具擋下「跨 JOB 混合 commit」

### 層 3：品管 gate 未覆蓋 title 欄位

修復前 `scripts/verify_ui_data_integrity.mjs --gate` 只檢查：

- D-INT-1 缺 answer 欄位 = 0
- D-INT-2 answer_index 越界 = 0
- D-INT-3 options 非 4 選項 = 0
- D-INT-4 loader normalizedAnswer 錯位 = 0

**沒有**檢查 `items[].title` 是否為佔位符 → 101 個 placeholder manifest 順利通過品管、上線顯示給學生。

## 四、連鎖崩壞路徑

```
[JOB-167~183 各自產題，邊產邊沒 commit，累積在 working directory]
    ↓
  需要批次為 G3-G6 建 manifest（擴充題庫規劃）
    ↓
  產題腳本呼叫 repair_manifests / auto_generate_questions
    ↓
❌ 找不到真實課名時 fallback 到 "L{N}"（層 1）
    ↓
  同時 AI 在無 KL4 課文素材情況下，從其他來源 scrape / hallucinate 題目
    ↓
❌ 產生的題目跟「該課」完全無關（G5 南一 L4 縣官審石頭 → 太陽公公題目）
    ↓
  JOB-184 執行 G5 社會出題時，一次性 commit 所有累積工作（層 2）
    ↓
❌ commit message 只記 JOB-184，101 個 manifest 被隱藏（層 2）
    ↓
  L1-3 verify gate 通過（因為沒檢查 title）（層 3）
    ↓
  部署到 production，學生看到「第 1 課 L1」
    ↓
  2026-04-20 使用者發現，JOB-205 啟動修復
```

## 五、防治措施（JOB-205 已實施）

### 5.1 層 1 修復：三支腳本 fallback 改 throw

| 檔案 | 改動 |
|:--|:--|
| `scripts/repair_manifests.js:63` | 若 `lesson_title / category / meta.title` 皆無 → `throw new Error(...)` |
| `scripts/auto_generate_questions.js:80`（`getBankMeta`）| 若 `title` 為空或 `^L\\d+$` → throw |
| `scripts/job184_g5s2_social_orchestrator.js:147` | 若 `meta.title` 為空或 `^L\\d+$` → throw |

**效果**：未來再跑產題腳本時，遇到缺 KL4 真實課名的 lesson JSON 會**立即中止並指向本文件**，不會產生新的佔位符或 AI 幻覺題目。

### 5.2 層 3 修復：品管 gate 加 D-INT-5 + 獨立稽核工具

| 新增 | 作用 |
|:--|:--|
| `scripts/verify_ui_data_integrity.mjs` D-INT-5 規則 | manifest `items[].title` 不得為 `/^L\\d+$/`；**warning 模式**（當前 42 檔未修完，硬擋會阻斷 commit）|
| `scripts/verify_no_placeholder_title.mjs`（新檔）| 獨立稽核工具，列出所有 placeholder manifest 與課數；供 pre-release 檢查 |

**後續升級路徑**：JOB-205 階段 3 補完大部分 title 後，把 D-INT-5 從 warning 升級為 error（gate 擋 commit）。

### 5.3 層 2 遺留：commit 紀律

**本 JOB 未處理**。建議未來獨立 engineering JOB 實作：
- Pre-commit hook 掃 `git diff --name-only` 範圍，若超過派工單 `任務邊界` 的檔案列表則警告
- 或於 `job_manager.js close` 時強制對照 commit 檔案清單 vs 派工單範圍

目前仰賴**開發者人工遵守**「一個 commit 一件事、message 誠實描述所有變更」。

## 六、未來再發生的預警

若下列訊號同時出現，高度可能是類似事故：

1. **單一 commit 改動 > 500 檔**（eccb974 改 4422 檔）
2. **commit message 只提一個 JOB 號但 diff 含多個 JOB 的 script 檔**
3. **新建 manifest 的 title 欄位為 `L\\d+` 或空字串**
4. **新建 lesson JSON 的 `meta.title` 缺失**
5. **相同 commit 同時新增 KL4 研究檔與產題腳本**（表示邊研究邊出題，沒分階段驗證）

觸發任一 → 立刻停下**檢查是否偏離派工單範圍**。
