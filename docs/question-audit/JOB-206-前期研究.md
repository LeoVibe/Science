### 1.3 判定方式
對每題閱讀 `question` + `options` + `explanation`（必要時含 `commonMisconception` / `scenario` / `blind_eval_mismatch.ai_reasoning`），依下列類別編號：

- **OK**：題目內容確實在講該 title 的課文
- **C1（scenario 誤用）**：題目符合該課，但 scenario 欄位被當作「考點分類」（如「主旨感悟」「詞彙運用檢核」）而非題幹情境前綴

### 3.2 外推 117 檔整體分佈（保守估計）

假設這 5 檔抽樣能代表 117 檔可疑檔案的極端樣本：

- **C1（scenario 欄位純語義誤用）**：**佔比 < 5%**。在 5 個抽樣檔中幾乎不存在「題目對但 scenario 只是考點標籤」的單純狀況；即便 scenario 形如「角色特質與情節檢核」這類考點分類（G3 L3 第 13 題），題目本身仍對應正確 title，屬 OK 不是 C1。
- **C2（錯放其他課文）**：**估計佔 55-70%**。這是最主要問題來源，尤其當多課次在同一批次產題時，模型把「類似情境」題錯連到不同 lesson 的 JSON 檔。
- **C3（主題憑空虛構）**：**估計佔 20-35%**。當模型對某課沒有研究素材時，常以「雨後的彩虹/太陽公公/老樹」等通用擬人化短文自行補題。
- **純 OK 檔案**：這 117 檔裡多數「混合」OK + C2/C3，很少是全檔都壞。

**換算題目量**：117 檔若平均 30-40 題，總題目約 3,500-4,700。
- C2 題目約 **1,900-3,300 題需下架重出**
- C3 題目約 **700-1,600 題需下架**
- **總計 2,600-4,900 題**（超過題庫可疑範圍的一半以上）

### 3.3 現象共通點

1. **盲測已偵測**：驗證 AI（Gemini-3.1-Flash-Lite）在 `blind_eval_mismatch.ai_reasoning` 欄位明確標註「題目內容與提供的課文完全無關」多達十餘次，但 `review_status` 仍 confirmed、`is_publishable: true`。**盲測信號被忽略**，成為上架題。
2. **有 `id` 欄位（格式 `Chi_G?_S?_{出版}_U?`）的題目才是早期「正牌」題**。其他大量題目缺 `id`，是後期批量補題產生的錯放。
3. **JOB-178 自動結案腳本**的 `review_notes` 標示「Match 且 CQI≥6.5」但實際盲測 `ai_selected: -1` 時仍放行，閘門有漏洞。
4. **課次間錯放為主**：同一批次產題時，不同 lesson 的題目被寫到錯誤的檔案裡。例如「美好生活的起點」是康軒 G3 S2 第一單元導言，題目被全部塞進 L1.json；「還差一點」「既然」「生活智慧」等相鄰課次的題目也彼此錯置。

## 四、scenario 規範 A/B/C 方案評比

### 4.1 規範定義對照

依 `question/README_出題與品管準則.md` §2.5：

> `scenario` (String)：題幹情境或引文描述

目前的 scenario 實際被當成三種東西混用：
- 情境前綴（例：`【在小明看到……時】`）— 這與 §2.5 定義相符
- 考點分類標籤（例：「角色特質與情節檢核」「分析心理狀態與情感」）— 語義誤用，但不算錯題
- 主題名詞（例：「雨後的彩虹」「太陽公公的笑容」）— **這些本身就是錯放題目的痕跡**

### 4.2 三方案矩陣對比

| 維度 | 方案 A（強制情境前綴） | 方案 B（可空） | 方案 C（分兩欄位） |
|:--|:--|:--|:--|
| **scenario 欄位內容** | 必為 `【...】` 情境前綴或空字串 | 允許任意或空 | `situation_prefix`（情境）+ `cognitive_tag`（考點） |
| **能否解決 C2/C3 錯放？** | **否** — scenario 格式化並不會辨識題目內容是否符合課文 | 否 | 否 |
| **能解決 C1 語義混用？** | 是（強制分離） | 部分（降低使用頻率） | **是**（欄位本身就分開） |
| **遷移成本（183 題抽樣推算全庫）** | 高：需清洗所有現有 scenario 到合規格式（估 15k+ 題） | 低：允許留空或保留 | **極高**：schema 變動、腳本變動、前端變動、library_config 變動 |
| **CQI-P 計分影響（P-D）** | 需調整：P-D 目前依 scenario 存在給 0.5 分，強制情境前綴會讓「記憶提取題」失分 | 幾乎無影響 | 需重寫 P-D 計分邏輯 |
| **對上架門檻可退題效果** | 弱：格式通過但內容仍可能錯放 | 弱 | 弱 |
| **前端顯示** | 情境前綴可直接塞題幹前段顯示 | 無一致規則 | 可分開樣式處理 |

### 4.3 重點判斷

**三方案任何一個都無法直接解決 C2/C3**。C2/C3 問題不是 scenario 欄位本身的語義混亂，而是**題目與 title 主題內容不匹配**。scenario 規範只能改善 C1，但 C1 在抽樣中幾乎不存在。

真正該先解決的是：
1. **題目內容是否符合 lesson title 的稽核機制**（需要 KL4 課文全文比對 + 模型判讀）
2. **盲測 `ai_selected: -1` 或 `ai_reasoning` 含「無關」字樣時自動下架**（現有閘門漏洞）
3. **回溯 `id` 欄位缺失的題目**（這些是後期補題產生的風險族群）

## 五、建議採納方案 + 理由

### 5.1 建議：**方案 B + 對 C2/C3 採另外獨立的稽核機制**

理由：

1. **scenario 欄位強制格式化對本次危機（C2/C3 錯放）幾乎無效**。現有 scenario 多數是語義誤用但題目仍正確（G3 L3 後段），或題目根本錯放（G5 L4 多數），強制格式化既不能救錯放題、也會毀掉現有正確的題目。
2. **C2/C3 錯放是比 scenario 欄位規範更嚴重的題庫品質危機**。應立刻優先處理內容錯放，而非先動 schema。
3. **方案 B 的好處**：允許 scenario 為空（或保留為「引文描述」語意），短期不破壞既有題庫；長期以「引文描述」為 scenario 正解，把考點分類轉移到 `topic` 欄位（§2.5 既有可選欄位）。
4. **方案 C 遷移成本過高**，在題庫內容本身都還不乾淨時去動 schema 等於雪上加霜，應留到內容稽核完成後再檢討。
5. **方案 A 的情境前綴強制化應延至 JOB-206 完結後**再評估；現階段即便看到 `【...】` 前綴也不保證題目屬於正確課文。

### 5.2 配套規範（scenario 欄位定義修正）

建議修訂 `question/README_出題與品管準則.md` §2.5 scenario 描述為：

> `scenario`（String，可選）：題幹情境引文描述；若題目有情境前綴（如 `【在 XX 場景】`），以此欄位承載或於 `question` 開頭使用。**禁止**用於考點分類，考點分類請寫入 `topic` 欄位。

並在 `evaluate_question_quality.js` P-D 計分規則補一條：**若 scenario 內容與 `meta.title` 主題名詞字面重疊但題目未引用該主題，觸發 C3 警示**。
