# Eidos 品質／上架／成熟度 層次定義

## 為什麼重寫（設計原則）

過去有 8 套交織的指標（KL／RM／CQI-P／CQI-V／QL／is_publishable／blind_evaluation／review_status），彼此重疊又互相綁死，產生兩個矛盾：「QL3 一題都上不了」「前台顯示的上架數比學生實際能做的多」。

本定義把它們收斂成**三條獨立的軸**，每條只回答一個問題：

| 軸 | 回答的問題 | 比喻 |
|:--|:--|:--|
| **成熟度** | 這課的「素材」準備到多齊全？ | 建材 |
| **品質** | 實際做出來的「題目」多好？ | 蓋好的房子 |
| **上架** | 這題「現在」能不能給學生看？ | 大門開不開 |

**三軸單向影響、各自獨立**：好建材*有機會*蓋出好房子，但不保證；好房子*預設*可以開門，但發現問題可隨時單獨關門。

---

## 軸一　題庫成熟度（素材潛力，內部）

**白話**：衡量「為了出這課題，研究素材備到多齊」。建材越好，越**有機會**做出好題——但**不保證**最終品質（施工沒做好，好建材也能蓋出爛房子）。

**嚴謹定義**：以單課為單位，用 RM0–RM3 記錄；判定以檔案實證為準。

| 代號 | 名稱 | 判定條件 |
|:--:|:--|:--|
| **RM0** | 骨架 | 僅課綱／關鍵字，無單課研究檔 |
| **RM1** | 素材 | 存在 KL4 單課研究紀錄（含課文全文） |
| **RM2** | 考古 | RM1 ＋ 存在 KL4 考古題與討論 |
| **RM3** | 透析 | RM2 ＋ 已通過盲測 |

- 素材檔案實體存於 `knowledge/`（KL 為其**目錄結構**，非品質指標）。
- RM 只記錄**素材狀態**，是「潛力」，**不等於**題目品質。

---

## 軸二　品質規範（成品結果）

**白話**：衡量「實際做出來的題目多好」。這是給客戶看的招牌。

### 對外品質標籤 QL1–QL5（**維持原始定義，不更動**）

| 等級 | 名稱 | 說明 |
|:--:|:--|:--|
| **QL1** | 課綱基礎 | 僅依課綱與關鍵字產出，學習目標不夠精準。 |
| **QL2** | 課文歸納 | 該課已完成 KL4 單課研究（有課文）；題目能具體歸納課程內容與精髓。 |
| **QL3** | 考古參考 | 該課額外完成 KL4 考古題與討論；誘答設計有實證基礎。 |
| **QL4** | 深思與盲測 | 用不同 Agent 進行盲測且通過；題幹與選項經實測精修。 |
| **QL5** | 專家認證 | 經多層次邏輯檢查、教師審閱與使用者回饋驗證。（未來期待） |

### 每題 QL 判定（可驗證、累積制）
- QL2：該課存在 KL4 單課研究紀錄
- QL3：QL2 ＋ 該課存在 KL4 考古題與討論
- QL4：QL3 ＋ 該題 `blind_evaluation === true`（盲測通過）
- 未達 QL2 → QL1
- 達 QL4 同時也算 QL3、QL2（累積）

### 每庫 QL（每 grade／semester／subject／publisher）
- 該庫達到 QL_X 以上的題目比例 ≥ 90% → 取最高達標等級為該庫 QL；皆未達 90% → QL1。

### 內部品質分數 CQI（輔助，不對外）
- **CQI-P**：出題結構分 0–10，**≥ 5.5 才可進盲測**
- **CQI-V**：盲測分 0–4
- 最終 CQI = CQI-P ＋ CQI-V
- CQI 是**流程關卡與追蹤分數**：不對外顯示、不直接定義 QL（QL 以上方可驗證條件為準）。

> **關鍵分界**：RM（素材／潛力）≠ QL（成品／結果）。素材齊全（RM3 潛力）的課，若出題或盲測沒做好，最終仍可能是低 QL。

## 軸三　上架許可（線上狀態，獨立閘門）

**白話**：衡量「這題現在能不能出現在學生面前」。這是一個**獨立開關**，與品質分開——好題也可能因臨時發現問題被單獨關掉。

### 單題上架旗標 `is_publishable`
- 該題是否被前端 loader 載入的**最終、唯一**依據。
- **預設可上**：品質達 QL3 以上 ＋ `review_status` 非 pending ＋ **通過 BIAS 驗證（該課「正解＝最長」比例 ≤ 40%，不分 QL3／QL4）** ＋ 無特殊下架原因 → `true`
- **例外下架（獨立性）**：任何題即使品質達 QL4，一旦發現特殊問題（答案爭議、不當內容、學生多次回報等），可單題設 `false` 獨立下架，**不影響同課其他題**。

### 兩級上架
| 庫品質 | 線上呈現 |
|:--|:--|
| **QL4** | 正式上架（前端無標記） |
| **QL3** | BETA 上架（前端標「BETA · 尚未嚴謹測試」） |
| **QL2 以下** | 不上架 |

### 課級上線門檻
- 該課 `is_publishable === true` 的題數 **≥ 25** → 該課可上線。

### 統計一致性（杜絕灌水）
- 對外顯示的「上架題數」＝ `is_publishable === true` 的實際題數（與前端 loader 實際載入一致），**不得以「整包達標即全算」估計**。

## 三軸關係（單向影響，各有獨立性）

```
 素材 RM ──有機會、不保證──▶ 品質 QL ──預設可上──▶ 上架 is_publishable
（建材／潛力）              （房子／結果）          （大門／許可）
                                                      ▲
                                    特殊問題可單題覆寫下架（獨立關門）
```

一句話：**RM 管「素材多好」、QL 管「題目多好」、is_publishable 管「這題現在能不能看」——三者分開，不互相綁死。**

---

## 降為「執行欄位」（不再是獨立層次）
| 欄位 | 角色 |
|:--|:--|
| `blind_evaluation` | 盲測是否通過（布林）→ QL4／RM3 的判定依據之一 |
| `review_status` | 審核流程狀態（pending／approved／manual_review）→ 影響 is_publishable |
| `KL` | `knowledge/` 研究檔案目錄結構 → 承載素材，非品質指標 |

## 與現行準則的差異（落實時需改）
1. **§4.6 上架門檻**：由「只 QL4 上架」放寬為「QL4 正式／QL3 BETA」兩級。
2. **generate_library_stats**：上架數改採逐題 `is_publishable`（已於 JOB-258 修正）。
3. **QL3 題上架機制**：需建立「QL3 達標即可設 is_publishable=true（標 BETA）」的回寫流程（目前 is_publishable 僅在盲測通過時設）。
4. RM 與 KL 的定位文字需在研究總綱同步釐清（RM＝素材潛力、KL＝目錄）。
