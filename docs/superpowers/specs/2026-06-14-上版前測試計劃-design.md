# 上版前測試計劃 — 設計文件 (spec)

## 1. 背景與目標

近一個月密集出題、重出題庫、修隱形課、修回饋功能、數英下架，累積 18 張 JOB（235~257）。期間暴露多個「閘門失效」問題（假綠燈測試、過時統計、隱形課、回饋缺 id）。本計劃要：

1. 建立一份**常駐、可重複跑的「上版前測試清單」SOP**（取代目前形同虛設的 `ei_release` 6 條）。
2. 用該 SOP 把**最近一個月 18 張 JOB 的改動逐張補驗證**一次。
3. 測試不只跑流程清單，還要**實際 UI 黑箱測試**與**每學期題庫抽檢**。

**成功標準**：SOP 文件可被任何 Agent/人重複執行；18 張 JOB 各有明確「已驗證/缺口」結論；前端關鍵流程與 60 個題庫組合經實際抽檢無重大缺陷。

## 3. 五個已知問題與解法（白話、具名）

### 問題 1：上版前「自動測試通過」是假綠燈
- **現況**：`ei_release` 第一條「`npm run test` 全數通過」，但 `apps/v3_eidos/src/data/questionLoader.test.ts` 8 測試中 6 個為既有失敗（mock 環境抓不到題目檔，回空陣列）。
- **解法**：修 `questionLoader.test.ts` 環境設定使 8/8 真通過；新增測試「每題必有 id」（守這次回饋 bug 根因）。
- **驗證**：`npm run test` 8/8 綠；故意移除 id 測試需變紅。

### 問題 2：題庫統計會過期而無人察覺
- **現況**：前台數字來自快照 `apps/v3_eidos/src/data/libraryStats.json`，題庫改動後需手動跑 `scripts/generate_library_stats.js`。G3 自然曾過期近兩個月（顯示 120/150，實為 200）。
- **解法**：把「重產快照 + 前台數字對帳」寫入 SOP L1，固定動作。
- **驗證**：快照數字＝實算數字，逐格一致。

### 問題 3：剛修好的回饋功能怕再被改壞
- **現況**：回饋 bug 剛修（`questionLoader.ts:230` 補 id fallback），但無任何測試在守。
- **解法**：自動測試守「題目有 id」+ e2e（`webapp-testing`）守「做題頁→問題回報→送出帶 id」。
- **驗證**：e2e 實跑回 200 且帶 id；列入 SOP L3。

### 問題 4：題目會「隱形」（隱形課）
- **現況**：JOB-254/255 揭露 `is_publishable` 誤標關閉 → 品質好且盲測過的課在前台消失，後台看不出。
- **解法**：SOP 加「應上架課數 vs 前台可見課數」對帳。
- **驗證**：兩數一致；不一致即列出隱形課。

### 問題 5：統計數字無第二來源覆核
- **現況**：前台題數/上架數全來自快照，快照自身對錯無獨立來源。
- **解法**：以「直接掃題庫 JSON 實算」為第二來源對帳並固化腳本。
- **驗證**：實算 vs 快照逐格一致。

## 4. 常態 SOP 五層（docs/上版前測試清單.md）

| 層 | 內容 | 手段 / Skill | 通過標準 |
|:--|:--|:--|:--|
| **L0 提交閘門** | golden cases、format consistency | pre-commit（自動） | commit 不被擋 |
| **L1 資料完整性** | `verify_ui_data_integrity --gate`；重產 libraryStats + 實算對帳（問題 2/5）；隱形課對帳（問題 4） | 腳本 | D-INT 0；快照=實算；無隱形課 |
| **L2 建置** | `npm run test`（問題 1 修復後）、`npm run build` 出 dist | `ei_release` | test 8/8、build 成功 |
| **L3 前端關鍵流程**（UI 黑箱） | 見 §6 清單 | `verify`/`webapp-testing` | 全項通過 |
| **L4 線上 smoke** | 部署後正式站關鍵頁 + 回饋實測 | 瀏覽器抽測 | 關鍵頁正常、回饋 200 |

## 6. 前端 UI 黑箱測試清單（L3，實際瀏覽器點）

當使用者操作，不看程式碼：
1. 首頁 → 選年級/科目/學期/版本流程
2. 答題流程：選答 → 確認答案 → 解析顯示正確
3. 結算頁分數正確
4. **回饋送出**：問題回報 → 送出 → 200 + 成功提示
5. **BETA 標記**：QL3 題庫（如 G5 國語）顯示、QL4 不顯示
6. **數英下架**：選單無數英、`/g4/mat` 直連被導回
7. 設定/profile 切換生效
8. 後台登入頁正常、`/api/settings` 回應
9. about 四分頁（關於/出題研究/更版/題庫總覽）顯示
10. 統計頁、科目/版本/年級切換不崩

## 7. 每學期題庫抽檢（60 組合）

**母體**：G3–G6 × S1/S2 × 國語/自然/社會 × 三版 = 60 個有題庫組合（數英已下架不檢）。

**兩段抽檢**：
- **程式面（全掃）**：腳本對 60 組合掃 — answer_index 越界、選項非 4、缺 answer、占位題、無 id。`verify_ui_data_integrity` 目前僅掃 S2 開放範圍，需擴及 S1 與全部組合。
- **UI 黑箱（抽樣）**：每年級每科至少抽 1 組合，瀏覽器實際作答，看題幹/選項/解析顯示正常、無亂碼占位。優先抽 S2 已上架 + S1 代表。

**抽檢判定**：程式面 0 error；UI 抽樣無顯示缺陷。發現問題記入 JOB-258 缺口清單，不在本計劃內修（範圍外另開單）。

## 8. 執行順序

1. 建 JOB-258、寫 `docs/上版前測試清單.md`
2. 修問題 1（questionLoader.test）→ L2 可真跑
3. 跑 SOP L0–L2（腳本 + build）
4. 18 張 JOB 逐張補驗證（可並行 subagent 讀 Report）
5. L3 前端 UI 黑箱（瀏覽器）
6. 每學期題庫抽檢（程式全掃 + UI 抽樣）
7. 彙整 → JOB-258 Report → 結案五步

## 9. 邊界
- 本計劃**只做測試與驗證 + 建立 SOP**；發現的題庫/功能缺陷記入缺口清單，**不在本計劃內修復**（範圍外另開單）。
- 不改規範文件（SOP 為新增文件，非既有規範）。
