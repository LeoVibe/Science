# Eidos 題庫評估規則 v2 — 課文非必要

## 0. 為什麼要 v2（這次的設計動因）

v1（2026-06-14）把「課文」當 RM1 的必要門票：沒課文 → 卡 RM0 → 全部 QL1 禁出題。但**課文現實上無法 100% 取得**，有些課就是拿不到課本內容。結果出現兩種壞情況：

1. 拿不到課文的課，要嘛永遠出不了題，要嘛**硬出後違規標 QL4 上架**（見 §5 實證）。
2. 出題的合法素材其實不只課文——**考古題反推、課綱確認元素、常識** 都是真實可用的來源，v1 沒承認它們。

v2 的核心轉變：**從「課文中心主義」改為「多元實證素材」**。課文不再是必要門票，而是 RM3/RM4 的實證素材之一，與考古題地位對等。

> 使用者拍板紀錄（2026-06-16）：
> - RM 決定 QL 天花板，**不綁死等於**（素材好不保證題好）。
> - **對外 QL1–QL5 定義一起改寫**（正式推翻 v1「對外維持原定義」的指示）。
> - RM1「常識」層**保留**；QL4 素材門檻 = **RM3 即可**（RM4 為超額素材）。
> - 上架門檻（2026-06-16 定案）：**QL2 以上可上架**，採三級標籤 **QL2＝Alpha／QL3＝Beta／QL4＝正式**；QL1 不上架。（此條修正同日稍早「QL3 以上才上架」的初版決定——使用者最終決定讓 QL2 以 Alpha 標籤露出，承擔「無實證素材題露給學生」的品質取捨。）

---

## 1. 三軸關係（單向、RM 決定天花板、各自獨立）

```
素材 RM ──決定品質上限──▶ 題目 QL ──QL3 起可上架──▶ is_publishable
（建材：常識/課綱/考古/課文）  （成品：要出題+盲測達標）   （大門：獨立開關）
```

一句話：**RM 管「素材多好」、QL 管「題目多好」、is_publishable 管「這題現在能不能看」——三者單向影響、不互相綁死。** RM 只決定 QL 的天花板；題實際多好還要看出題與盲測。

---

## 2. 軸一　RM 素材成熟度（重定義）

以單課為單位，記錄該課「出題素材備到多齊」。判定以檔案實證為準。

| 代號 | 名稱 | 素材條件 | 對照 v1 |
|:--:|:--|:--|:--|
| **RM0** | 骨架 | 只有課名／課綱關鍵字，**連題都還沒出** | 同 v1 |
| **RM1** | 常識 | 僅憑學科常識能出題（無課綱細項、無考古、無課文）| 新增 |
| **RM2** | 課綱 | 有課綱對應的課程元素，能確認「這課要教什麼」 | 取代 v1 RM1 |
| **RM3** | 實證 | RM2 ＋（考古題 **或** 課文，二者之一）| 重定義 |
| **RM4** | 完備 | RM2 ＋ 考古題 ＋ 課文 **都齊** | 新增（v1 最高 RM3）|

**關鍵改動**：課文從「RM1 必要門票」降為「RM3/RM4 的實證素材之一」。**考古題與課文地位對等**——有任一個即 RM3，兩個都有才 RM4。

## 3. 軸二　QL 品質（對外改寫）

### 3.1 對外品質標籤 QL1–QL5（**v2 改寫**）

| QL | 新名稱 | 素材天花板 | 達標還需 | 舊名稱（v1）|
|:--:|:--|:--:|:--|:--|
| **QL1** | 常識題 | RM1 | 僅憑常識出題，無課程錨點 | 課綱基礎 |
| **QL2** | 課綱對應 | RM2 | 題目對應課綱課程元素 | 課文歸納 |
| **QL3** | 實證參考 | RM3 | QL2 ＋（考古 **或** 課文之一）＋通過**基礎檢查** | 考古參考 |
| **QL4** | 盲測淬煉 | RM3 | QL3 ＋ 素材元素清楚對應題庫 ＋ **盲測通過** ＋ **三大檢查** | 深思與盲測 |
| **QL5** | 專家認證 | RM3＋ | QL4 ＋ 多層邏輯＋教師審閱＋使用者回饋（未來）| 專家認證 |

### 3.2 每題 QL 判定（可驗證、累積制）
- QL1：素材達 RM1（能憑常識出題）
- QL2：素材達 RM2（有課綱元素對應）
- QL3：素材達 RM3（考古或課文之一）＋ 通過基礎檢查
- QL4：QL3 ＋ `blind_evaluation === true`（盲測通過）＋ 通過三大檢查
- 達 QL4 同時也算 QL3、QL2（累積）

### 3.3 每庫 QL（每 grade／semester／subject／publisher）
- 取「使該庫達 QL_X 以上題目比例 ≥ 90% 成立」的**最高** X 為該庫 QL。
- 例：≥QL4 佔 92% → 庫 QL4；≥QL4 僅 80% 但 ≥QL3 佔 95% → 庫 QL3；連 ≥QL2 都未達 90% → 庫 QL1。

### 3.4 內部品質分數 CQI（輔助，不對外，沿用 v1）
- CQI-P 出題結構分 0–10，**≥ 5.5 才可進盲測**；CQI-V 盲測分 0–4；最終 CQI = CQI-P＋CQI-V。
- CQI 是流程關卡與追蹤分數，不對外、不直接定義 QL。

## 4. 檢查機制（QL3／QL4 的品質閘門）

| 檢查項 | 內容 | 生效級別 |
|:--|:--|:--|
| 洩答清除 | 選項無「這也是作者想強調的…」等出題後設評語 | QL3 起（基礎）|
| 長度 BIAS | 該課「正解＝唯一最長」比例 ≤ 40%（不分 QL3／QL4，**上架硬門檻**）| QL3 起（基礎）|
| 文本錯位 | 題幹／選項引用須對應該課素材（課文或考古題或課綱元素）| QL3 起（基礎）|
| 盲測 | 不同 Agent 盲讀作答，Match 通過 | QL4 |
| 題幹吻合度 | 題目確實對應素材元素（非離題、非編造）| QL4（三大檢查）|
| 選項隨機度 | 正解位置不集中於固定索引 | QL4（三大檢查）|

> 「基礎檢查」＝洩答／長度 BIAS／文本錯位，QL3 上架前必過。「三大檢查」＝題幹吻合／選項隨機度／長度 BIAS，QL4 升級時驗。長度 BIAS 兩級都管，是上架硬門檻。

## 5. 軸三　上架許可 is_publishable

### 5.1 三級上架（v2 定案）
| 庫品質 | 線上呈現 |
|:--|:--|
| **QL4** | 正式上架（前端無標記）|
| **QL3** | Beta 上架（前端標「Beta · 尚未嚴謹測試」）|
| **QL2** | Alpha 上架（前端標「Alpha · 最早期實驗，素材未經實證」）|
| **QL1 以下** | **不上架** |

### 5.2 單題旗標 `is_publishable`
- 前端 loader 載入的最終唯一依據。
- **預設可上**：QL2 以上 ＋ `review_status` 非 pending ＋ 通過基礎檢查（含長度 BIAS ≤ 40%）＋ 無特殊下架原因 → `true`。
- **例外下架**：任何題即使 QL4，發現特殊問題（答案爭議、不當內容、學生回報）可單題設 `false` 獨立下架，不影響同課其他題。

### 5.3 課級上線門檻（沿用 v1）
- 該課 `is_publishable === true` 的題數 ≥ 25 → 該課可上線。

### 5.4 統計一致性（沿用 v1）
- 對外「上架題數」＝ `is_publishable === true` 的實際題數，不得「整包達標即全算」。

## 6. 連帶處置：三下社會翰林 177 題（觸發本次改版的案例）

### 6.1 查證結果（2026-06-16 實查，非推估）
| 查核點 | 結果 |
|:--|:--|
| 題庫規模 | 總 180 題（L1–L6），上線 `is_publishable=true` 共 **177** 題、全標 **QL4** |
| KL4 課文（單課研究紀錄）| L1–L6 **全 RM0**，明文「尚未取得翰林版課文，本節為空白」 |
| KL4 考古題（考古題與討論）| L1–L6 **全 RM0、全 40 行空殼**，明文「尚無考古題，請搜尋 tcool.cc 或段考卷後填入」 |
| 題庫 JSON 來源欄位 | **無**任何考古／來源欄位（無 source／past_exam）|
| `commonMisconception` 欄位 | 存在，但為**出題 LLM 當下生成的假設迷思**，非真實考古題萃取 |

→ 這 180 題**課文沒有、考古題也沒有**，純靠「課綱元素＋LLM 常識」出題。

### 6.2 v2 判定與處置
- **判定**：有課綱元素、無考古、無課文 = **RM2 → 天花板 QL2**。現行標 QL4 是 v1 缺漏（JOB-266 `5ae1aa9f` 只做 BIAS、沒查素材成熟度），須**從 QL4 降回 QL2**。
- **處置路徑（2026-06-16 定案：降階不下架，改標 Alpha 續上）**：
  1. **降為 QL2**、`quality_level="QL2"`、`is_publishable=true` **維持上架**，前端顯示 **Alpha** 標籤；`review_notes` 註記「QL2 Alpha · 無課文無考古、待補考古題升 RM3」。
  2. **補考古題**（tcool.cc 已建 708 份索引，考古題比課文好拿）→ KL4 升 RM2→RM3。
  3. 依考古題重新出題／校正，走盲測＋三大檢查 → 升 QL3（Beta）或 QL4（正式）。
  4. 升級後前端標籤自動由 Alpha → Beta／正式。

> 此案例證明 v1 漏洞：素材成熟度未納入升級與上架的硬性檢查，導致 RM0/RM2 題能標 QL4 上線。v2 把「素材天花板」做成 QL 判定的前置條件，堵住此洞。

## 8. 邊界
- 本 spec 只定義規則；規範正文修改與題庫處置另開 JOB 執行。
- 「素材天花板」判定需可程式化（讀 KL4 檔的 RM 標記＋題庫 JSON 欄位），避免再靠人工自律。
- RM 判定以**檔案實證**為準（KL4 檔頭的 RM 標記、考古檔是否非空、課文節是否非空）。
