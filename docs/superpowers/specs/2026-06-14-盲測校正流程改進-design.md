# 盲測＋BIAS 校正流程改進 — 設計文件

## 1. 背景：這 session 揭露的品質問題

對三~六下題庫做盲測升級時，連續發現出題產生器（gpt-5.5 / Codex）留下的系統性瑕疵：

1. **洩答標註**（已部分修）：錯誤選項末尾掛「這也是作者想強調的重點之一」「（與課文重點不符）」「（此選項偏離課文重點。）」等出題後設評語，等於告訴學生哪些是陷阱。全站 486 題、其中 380 題已上架。已清除（commit 1d0c5442、920debb9）。
2. **正解最長 BIAS**：三下國語 47-66%、社會 54-74%、四下國語 56%／自然 57%／社會 51%——學生可用「選最長」猜對。canonical 腳本 G3/G4 用 75% 門檻＋數理豁免，所以這些 40-74% 沒被擋。
3. **文本錯位**：題目對錯課文（如康軒 L1《許願》前 3 題題幹引用「美好生活的起點」，課文中 0 次）。
4. **QL4 標準漏洞**：QL4＝盲測通過，但盲測不檢查 BIAS／洩答，所以有瑕疵的題盲測過就上架。已補規範（BIAS 為上架硬門檻，不分 QL3/QL4，commit 59faa5d4）。

## 2. 紅隊盤點：現有「盲測＋校正」流程的 10 缺漏

**直接風險（校正會製造新問題）**
1. 改錯選項可能改出第二個正解（一題多解）——無「校正後重驗單一正解」關卡
2. 校正後沒重新盲測——盲測的是舊選項，校正後新選項未驗
3. 校正可能改壞中文／改變難度——只靠 subagent 自律

**盲測根本侷限**
4. Match ≠ 好題（100% Match 可能是題太簡單、誘答無鑑別度）
5. 單一來源驗證偏誤（盲測 subagent 都是 Claude，標準同源）

**只治下游**
6. 文本錯位等暴露出題流程壞了——光校正是補破網，產生器不修會一直再犯
7. 這些題當初怎麼通過舊盲測上架的？舊盲測流程本身有洞

**驗證與範圍**
8. 抽樣複核覆蓋率太低（只抽 3 題）；6 個 subagent 標準可能不一致
9. BIAS 只修「正解最長」一種（還有答案位置集中、句式完整度、否定詞陷阱）
10. 校正後要回歸測試（D-INT、前端顯示）

## 3. 決策（使用者 2026-06-14）

- **根本目標：先堵源頭再補存量**
- **必納入**：#1 校正後重驗單一正解、#2 校正後重新盲測、#6/#7 修出題流程、#8 提高複核覆蓋率

## 4. 改進設計

### 階段一　堵源頭（治本，優先）
1. **調查**：定位出題產生器（出題腳本／Codex prompt）與舊盲測流程，找出為何產生洩答標註／文本錯位／BIAS。
2. **修源**：
   - 出題端：prompt／腳本加防呆——禁止後設標註、強制 KL4 課名對應檢查、選項長度平衡
   - 盲測／上架端：把「BIAS／洩答／文本錯位」做成**自動閘門腳本**，commit 與上架前擋下

### 階段二　升級校正流程（治存量，每題八步）
1. 【讀取證明】回報從 KL4 單課研究紀錄讀到的課文整行原文（PM 可 grep 核對）
2. 【盲讀作答】只看 scenario+question+options 推理答案，比對 answer_index
3. 【文意＋逐題引用】引用課文具體一句支持答案（PM 可 grep 核對句在課文且支持答案）
4. 【迷思檢查】commonMisconception 欄位：存在？對應考古題真實迷思？與某錯選項對得上？
5. 【深入度】回報 taxonomy（literal/inferential/applied），不主觀打分
6. 【BIAS 校正】若正解唯一最長，重寫過短錯選項平衡長度（不改正解/答案/題意/不洩答）
7. **【新增】校正後重驗單一正解**：確認校正後四選項只有 answer_index 對、其餘三個明確錯（防一題多解）
8. **【新增】校正後重新盲測**：用校正後新選項再盲讀一次，確認仍 Match（盲測最終版本）

判定：八步全過 → 升 QL4；文意錯位／一題多解／Mismatch／深入度不足 → review_status=pending，不升級。

### 複核機制（全量，非抽樣）
- subagent 回報**每題**證據（讀取證明行、文意引用句）
- PM 腳本**自動 grep 核對全部**引用句是否真在 KL4
- 收尾：evaluate（BIAS 比例 ≤40%）＋ D-INT（答案對位）＋ 跨 subagent 一致性
