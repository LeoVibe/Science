## 一、研究動機：為什麼現行 CQI v1 需要演化？

現行 CQI v1 的核心理念是**「防止 AI 生出劣質題目」**，著重於格式防呆（選項長度偏差、字數門檻）。但在一年的實戰經驗中浮現的問題是：

> **「一道 CQI 9.0 的題目，可能用字遣詞超過該年級學童的閱讀能力，也可能根本不在課綱範圍內。」**

這代表 CQI v1 是一個「工程品質指標」，而不是一個「教學品質指標」。CQI v2 的目標是將兩者融合。

## 二、十維度逐項深度論述

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### A. 選項對稱性 (Option Symmetry)
**━━━ 保留維度 ━━━**

| 項目 | 內容 |
| :--- | :--- |
| **v1 配分** | 3.0 |
| **v2 建議配分** | 2.0 (下調) |
| **下調理由** | 此維度解決的是「猜題技巧」問題，屬於工程防呆。在十維度體系中，理應讓渡更多權重給教學價值維度。 |
| **執行邏輯** | 不變。若 `answer_index` 對應的選項為四選項中最長者且非全等長 → 得 0 分；否則得 2.0 分。 |
| **腳本實作** | 延用現有 `evaluateQuestion()` 中的 `isLongestAnswer` 邏輯，調整滿分值即可。 |

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### B. 情境深度 (Scenario Depth)
**━━━ 保留維度，邏輯升級 ━━━**

| 項目 | 內容 |
| :--- | :--- |
| **v1 配分** | 3.0 |
| **v2 建議配分** | 2.0 (下調) |
| **下調理由** | 「字數」是情境深度的必要條件但非充分條件。v2 應將多餘的權重重新分配給「課綱對齊」等更高教學價值的維度。 |
| **執行邏輯（改良）** | **二層評估**：(1) 字數門檻（沿用），(2) 是否包含「情境標籤」（如 `【在學校大掃除時】` 或引號對話框）。兩項各佔 1.0 分。 |
| **腳本實作** | 字數檢查延用。新增正則 `/(【.+?】|「.+?」)/` 匹配情境標籤或對話框，命中 ≥1 次即得第二個 1.0 分。 |

```javascript
// 虛擬碼範例
const hasContextTag = /【.+?】/.test(questionText) || /「.+?」/.test(questionText);
const depthScore = (qLen >= threshold ? 1.0 : 0.5) + (hasContextTag ? 1.0 : 0);
```

### C. 認知層次標註 (Cognitive Taxonomy)
**━━━ 保留維度 ━━━**

| 項目 | 內容 |
| :--- | :--- |
| **v1 配分** | 2.0 |
| **v2 建議配分** | 1.5 (微調) |
| **執行邏輯** | 不變。`inferential`/`applied`/`critical` → 1.5；`literal` → 0.75。 |
| **延伸思考** | 此維度的「品質感知」函數被維度 G（認知成熟度匹配）分擔了部分責任，因此可微降。 |

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### D. 結構完整度 (Structural Integrity)
**━━━ 保留維度 ━━━**

| 項目 | 內容 |
| :--- | :--- |
| **v1 配分** | 2.0 |
| **v2 建議配分** | 1.0 (下調) |
| **下調理由** | 欄位「存不存在」是基礎門檻，不應佔過多權重。v1 中此維度過度獎勵了「有寫但寫不好」的情況。 |
| **執行邏輯** | 簡化為：`explanation` > 10 字 → 0.5 分；`commonMisconception` 或 `scenario` 存在 → 0.5 分。 |

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### E. 🆕 易讀性 (Readability)
**━━━ 新增維度 ━━━**

| 項目 | 內容 |
| :--- | :--- |
| **v2 建議配分** | 1.0 |
| **為何需要** | 一道用了多個「成語」或「罕見疊字」的三年級題目，即使 CQI v1 得高分，學生根本讀不懂。 |
| **執行邏輯** | 計算題幹 + 所有選項的**平均字元數/句**與**罕用字比例**。依年級分級：（低年級：平均句長 ≤ 15 字為佳；高年級：≤ 25 字為佳）。 |
| **配分規則** | 平均句長在該年級合理範圍內 → 0.5 分；無超綱罕用字（可比對教育部常用字表前 N 級）→ 0.5 分。 |
| **自動化可行性** | ✅ **高**。可用 `split(/[，。？！；：]/g)` 斷句計算平均句長。罕用字檢查可引入靜態字頻表（如教育部常用國字標準字體表）。 |

```javascript
// 虛擬碼範例
function readabilityScore(text, grade) {
  const sentences = text.split(/[，。？！；：]/g).filter(s => s.trim());
  const avgLen = sentences.reduce((a, s) => a + s.length, 0) / sentences.length;
  const gradeLimit = grade <= 2 ? 15 : grade <= 4 ? 20 : 25;
  return avgLen <= gradeLimit ? 0.5 : 0;
}
```

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### F. 🆕 課綱對齊度 (Curriculum Alignment)
**━━━ 新增維度 ━━━**

| 項目 | 內容 |
| :--- | :--- |
| **v2 建議配分** | 1.0 |
| **為何需要** | 題目可能「有趣且精美」但完全偏離該課次的學習指標。目前沒有任何機制驗證題目是否真的在考課綱要求的內容。 |
| **執行邏輯** | 檢查題目對應的 `lesson_id` 是否存在於 `knowledge/課綱研究/` 下的發展綱要中，且該課次的 `Curriculum Matrix` 區塊是否包含與題幹相關的關鍵字。 |
| **配分規則** | 對應課次在研究檔中有 Curriculum Matrix 記錄 → 0.5 分；題幹中出現該矩陣記載的核心關鍵字 ≥ 1 個 → 再得 0.5 分。 |
| **自動化可行性** | ⚠️ **中**。需要從 MD 檔中解析 Curriculum Matrix 的關鍵字列表，並進行題幹關鍵字匹配。可行但需要前置建設（將研究檔結構化）。 |
| **挑戰** | 研究檔的格式尚未完全統一，需先標準化 Curriculum Matrix 的 keyword 提取方式。短期建議：先以「研究檔是否存在」作為 0.5 分門檻，關鍵字匹配列為 Phase 2。 |

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### G. 🆕 認知成熟度匹配 (Cognitive Fit)
**━━━ 新增維度 ━━━**

| 項目 | 內容 |
| :--- | :--- |
| **v2 建議配分** | 0.5 |
| **為何需要** | 皮亞傑理論指出，低年級（7-9 歲）處於具體運思期，不應大量出現需要抽象推理的 `critical`/`evaluative` 題型。反之，高年級若全是 `literal` 則太無挑戰。 |
| **執行邏輯** | 依據 `README_出題設計準則.md` 已定義的「跨年級動態配比建議」，檢驗**全檔**的 taxonomy 配比是否符合：低年級 6-3-1、中年級 4-4-2、高年級 2-3-5。 |
| **配分規則** | **此為全檔級指標**，非單題。全檔 taxonomy 配比落在建議範圍 ±15% 內 → 每題加 0.5 分（以檔級加分方式攤回每題）。 |
| **自動化可行性** | ✅ **高**。已有 `taxCount` 統計邏輯，僅需增加年級配比比對。 |

```javascript
// 虛擬碼範例
function cognitiveFitBonus(taxCount, grade, totalQuestions) {
  const ideal = grade <= 2 ? { literal: 0.6, inferential: 0.3, applied: 0.1 }
              : grade <= 4 ? { literal: 0.35, inferential: 0.4, applied: 0.25 }
              :              { literal: 0.15, inferential: 0.3, applied: 0.55 };
  const actual = {
    literal: taxCount.literal / totalQuestions,
    inferential: taxCount.inferential / totalQuestions,
    applied: (taxCount.applied || 0) / totalQuestions
  };
  const drift = Object.keys(ideal).reduce((sum, k) => sum + Math.abs(ideal[k] - actual[k]), 0);
  return drift <= 0.30 ? 0.5 : 0; // 總偏移量 <= 30% 視為通過
}
```

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### H. 🆕 誘答鑑別度 (Distractor Quality)
**━━━ 新增維度 ━━━**

| 項目 | 內容 |
| :--- | :--- |
| **v2 建議配分** | 1.0 |
| **為何需要** | 這是黑箱測試的核心產出。若 AI 在看不到答案的情況下也能輕鬆選對，代表誘答品質不足；若 AI 被某個誘答干擾，則代表該題具有真正的「鑑別效能」。 |
| **執行邏輯** | 須結合「黑箱測試規範」的 Match/Mismatch 結果。**單題級**：AI 盲測答對 → 0.5 分（代表題目邏輯自洽）；AI 盲測答錯但原始正確答案確實合理 → 1.0 分（代表誘答極強）。AI 盲測答錯且原始答案確有爭議 → 0 分（需人工介入）。 |
| **配分規則** | Match + 無爭議 → 0.5；Mismatch + 原答案自洽 → 1.0（高鑑別度獎勵）；Mismatch + 原答案有瑕疵 → 0.0。 |
| **自動化可行性** | ⚠️ **低（需 LLM 介入）**。黑箱測試本身需要 LLM 推論，無法純粹由腳本完成。建議實作為**離線批次任務**，將結果回寫 JSON 的 `blind_test_result` 欄位，再由腳本讀取計分。 |

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### I. 🆕 文化公平性 (Cultural Equity)
**━━━ 新增維度 ━━━**

| 項目 | 內容 |
| :--- | :--- |
| **v2 建議配分** | 0.5 |
| **為何需要** | 高社經情境（如搭飛機、買名牌）會系統性地不利於偏鄉學童。這是教育測驗的基本倫理。 |
| **執行邏輯** | 建立一個「高社經/城市偏見關鍵字清單」（如：機場、百貨公司、出國旅遊、高鐵商務艙、信用卡...），掃描題幹與選項。 |
| **配分規則** | 未命中任何偏見關鍵字 → 0.5 分；命中 ≥ 1 → 0 分（並標記 WARNING）。 |
| **自動化可行性** | ✅ **高**。純粹關鍵字比對，維護一個靜態 JSON 清單即可。 |
| **風險** | 關鍵字清單可能不夠細緻（例如「超市」在偏鄉也常見，但「百貨公司週年慶」則否）。建議逐步迭代。 |

### ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
### J. 🆕 研究支撐度 (Research-Backed)
**━━━ 新增維度 ━━━**

| 項目 | 內容 |
| :--- | :--- |
| **v2 建議配分** | 0.5 |
| **為何需要** | 已有 `checkResearchSupport()` 函式可判定研究檔完整度。一道有 R3 轉化策略支撐的題目，其迷思設計的真實性遠高於 AI 憑空猜測。 |
| **執行邏輯** | 延用現有 `checkResearchSupport()` 函式的判定結果，將 ceiling 轉換為分數。 |
| **配分規則** | ceiling 為 L4 → 0.5 分（研究完整）；L3 → 0.3 分；L2 以下 → 0 分。 |
| **自動化可行性** | ✅ **已實作**。直接引用現有函式即可。 |

> **設計哲學變更**：
> - 維度 **I（文化公平性）** 改為**扣分制**而非加分制。觸發偏見關鍵字 → 扣 0.5 分。理由：公平性是「不能違反」的底線，而非「做到了就加分」的獎勵。
> - 維度 **J（研究支撐度）** 沿用現有的**天花板機制**。它不直接加分，而是限制 QG 等級的最高上限（無研究支撐 → 最高只能 L3）。

## 五、與現行 QG (Quality Gate) 的關係

CQI v2 **不取代** QG (L1-L5)。兩者的關係維持不變：
- **CQI** = 連續值評分（0.0-10.0），告訴你「這題有多精細」
- **QG** = 離散門檻（L1-L5），告訴你「這份檔案能不能上架」

**新增的互動規則**：
- 若 CQI v2 中維度 I 觸發（文化偏見）→ 自動降級 QG 為 L2
- 若 CQI v2 中維度 H 的 Mismatch 比例 > 40% → QG 加註警告
