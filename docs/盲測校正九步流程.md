# 盲測＋校正 九步流程（標準作業）

## 為什麼有這份文件（這 session 的發現）

出題產生器（gpt-5.5/Codex）留下三類系統性瑕疵，舊盲測沒擋住就上架：
1. **洩答標註**：錯誤選項掛「這也是作者想強調的重點之一」「（與課文重點不符）」等出題後設評語＝告訴學生哪個是陷阱。
2. **正解最長 BIAS**：正解總是最長選項（三下國語 47-66%），學生「選最長」就中。
3. **文本錯位**：題目對錯課文（題幹引用不在該課課文的內容）。
4. **原題答案標錯**：explanation 寫的答案 ≠ answer_index。

QL4 標準原本只看「盲測通過」，不檢查上述，所以瑕疵題照樣上架。本流程補齊。

## 鐵律（違反即無效）

- 🔒 **不改 正解內容／answer_index／題幹題意**；只重寫過短的「錯誤選項」平衡長度、清洩答。
- 🔴 **subagent 不得再自行派孫 agent**——孫 agent 寫入不落地（實證：6 個孫 agent 全報成功但檔案與 HEAD 逐位元組相同）。一律親自完成。
- ✅ 寫入後須以 git diff／md5 對照 HEAD **驗證落地**。
- 留下可被 PM grep 交叉核對的證據（讀取證明行、文意引用句）。

## 九步流程（每題）

1. **讀取證明**：貼出從該課 KL4 單課研究紀錄讀到的「課文全文」整行原文（PM 可 grep 核對真讀）。
2. **盲讀作答**：只看 scenario+question+options 推理答案索引，比對 answer_index（Match/Mismatch）。
3. **文意＋逐題引用**：引用課文具體一句支持答案（PM 可 grep 核對句在課文且支持答案）。
4. **迷思檢查**：commonMisconception 欄位 存在？對應考古題真實迷思？與某錯選項對得上？
5. **深入度**：回報 taxonomy（literal/inferential/applied），不主觀打分。
6. **BIAS 校正**：若正解唯一最長，重寫過短錯選項平衡長度（守鐵律）。
7. **校正後重驗單一正解**：確認校正後四選項只有 answer_index 對、其餘三個明確錯（防一題多解）。
8. **校正後重新盲測**：用校正後新選項再盲讀一次，確認仍 Match（盲測最終版本）。
9. **解析一致性檢查**：核對 explanation 描述的答案 == answer_index；不符代表原題答案可能標錯。

**判定**：九步全過 → 升 QL4（approved/publishable）；文意錯位／一題多解／Mismatch／解析不一致／深入度不足 → review_status=pending、is_publishable=false，記原因待人工複核。

## 複核（全量，非抽樣）

- subagent 回報每題證據；PM 腳本自動 grep 核對全部引用句真實性。
- 收尾跑 evaluate（BIAS 正解最長 ≤40%）＋ D-INT（答案對位）＋ 跨組合一致性。
