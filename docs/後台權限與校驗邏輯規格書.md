# 🛡️ 後台權限與校驗邏輯規格書 (Manager Specification)

**最後修訂時間：** 2026-02-24
**存放路徑：** `web_manager/後台權限與校驗邏輯規格書.md`
**目的：** 說明 Eidos 管理後台「題庫健康度校驗」與「活動軌跡追蹤 (Activity Logger)」的規格與技術實作邏輯。

---

## 1. 佈署模式與靜態機制 (Deployment & Static Config)
- **介面技術：** 採用 React (Vite) 組件開發，整合在 `/admin` 路由。
- **UI 狀態同步核心：** 為了確保前端效能並避免跨來源請求，後台的「題庫開放清單、各版單元數、題目數與品質層級」**不採取即時硬碟掃描**。
- **資料來源：** 介面渲染完全依賴 `apps/v3_eidos/src/data/libraryStats.json`。因此，任何新增或刪除題庫的腳本/操作，必須連帶更新此靜態註冊表，否則管理後台將會出現資料不同步（例如顯示 0 單元）。

## 2. 健康檢查儀表板：靜態校驗規則 (Static Diagnostics)
後台須能讀取 `manifest.json` 與題目 JSON，並透過 React 介面呈現視覺化報表，執行以下層級的斷言檢查：

### 📁 檔案層級檢查
1. **Orphan Check (孤兒檢查)：** 確保平台目錄下所有的 JSON 檔案，都有登記在其所屬目錄的 `manifest.json` 裡面。
2. **Missing Check (遺失檢查)：** `manifest.json` 中定義的 `file` (或 `items` 中宣告的 `path`)，其對應的實體 JSON 檔案必須真實存在。

### 📝 格式層級檢查 (Schema Validation)
1. 確保題庫 JSON 的 `questions` 為陣列且長度大於 `0`。
2. 答案欄位統一：確保遵守平台最新推薦規格 (格式 A')，即包含 `answer_index` (0-based) 與題解解析 `explanation`。

### 🧠 邏輯層級檢查 (Logic Assertions)
1. **答案索引防護：** 確保 `answer_index` 的數值介於 `0` 到 `options.length - 1` 之間，避免點選越界。
2. **選項數量檢查：** `options` 陣列長度必須通常為 `4`（有例外需警告但不阻攔）。

## 3. 活動軌跡與成效追蹤 (Activity Logger)
為了分析使用者行為與平台成效，後台引入了免登入的身份追蹤與日誌機制：

1. **唯一識別碼 (Device ID)：**
   - 透過 `getOrCreateDeviceId()` 函式生成 UUID v4，並儲存於使用者的 `localStorage` 中 (`EIDOS_DEVICE_ID`)。
2. **本機緩存與雲端同步：**
   - 使用者動作（如 `view_lesson`, `start_quiz`）會被封裝為事件物件寫入 `localStorage` (`EIDOS_ACTIVITY_LOGS`)，最多快取 500 筆。
   - 前端提供 `syncToCloudflare()` 方法，定期將資料打向 Cloudflare Worker 的 `/api/activity`。
3. **KV 雲端儲存 (D1 / KV)：**
   - 接收的 Worker 負責將資料存入 Cloudflare KV (命名空間：`ACTIVITY_LOGS`)。
4. **管理後台雙視圖：**
   - **使用統計 (`AdminUserInsights`)**：聚合視圖，調用 `/api/activity/insights` 呈現各 Device ID 的首次/最後活動時間與活躍天數。
   - **行動管理 (`AdminTestRunner`/Activity)**：原始日誌列表，調用 `/api/activity` 呈現依時間排序的原始動作，供行為軌跡還原與系統除錯。
