# 上版前驗證標準

`last_updated`: 2026-04-19
`updated_by`: Claude Code (claude-opus-4-7)

**文件定位**：本文件定義 Eidos 專案從開發分支合併至 `main` 並推送部署（觸發 GitHub Pages / Cloudflare Pages）前的強制驗證清單。每次上版派工單（`job_type: release_validation`）必須逐項打勾並附佐證。

## 文件起源

2026-04-18 JOB-188 「上版前實質驗證執行」結案後上線；2026-04-19 發現 `questionLoader.ts` 誤讀 `q.answer` 導致全站 12,911 題前端顯示 A 為正解（真實 `answer_index` 忽略）。回溯為什麼沒抓到：

1. 盲測（`run_blind_eval.js`）走自己的資料解析，不經前端
2. Unit test 合成資料未覆蓋 production 格式（`data.meta + data.questions[*].answer_index`）
3. JOB-188 §B 瀏覽器驗證的 ✅ 標準是「頁面不崩、能到達結果頁」，**沒有一條是「UI 標綠色的選項 = JSON `answer_index` 對應的選項」**

本文件將此教訓制度化：UI 與資料的一致性必須顯式驗證，不能靠「測試不崩」代表正確。

## 一、驗證三層次（必須全綠才上版）

### L1｜自動化腳本（pre-commit 擋關）

| # | 腳本 | 檢查內容 | 預期 |
|:--:|:--|:--|:--|
| L1-1 | `scripts/test_golden_cases.js` | 黃金測資品質評分回歸 | 通過 |
| L1-2 | `scripts/verify_format_consistency.js` | Manifest 格式一致性 | 通過 |
| L1-3 | `scripts/verify_ui_data_integrity.mjs --gate` | UI ↔ 資料一致性（`answer_index` 在 options 範圍、loader 推導正確） | 0 違規（開放範圍 G3-G6 × S2 + is_publishable !== false） |

以上 3 關已掛 `.git/hooks/pre-commit`，任何 commit 失敗即擋下。

### L2｜單元測試與 e2e 測試（CI / 本地跑）

| # | 測試 | 位置 | 執行指令 |
|:--:|:--|:--|:--|
| L2-1 | `questionLoader.test.ts` 8 個案例（含 production-format 回歸） | `apps/v3_eidos/src/data/questionLoader.test.ts` | `cd apps/v3_eidos && npx vitest run questionLoader` |
| L2-2 | `answer-integrity.spec.ts` UI 標綠色 === JSON answer_index | `apps/v3_eidos/tests/answer-integrity.spec.ts` | `cd apps/v3_eidos && npx playwright test answer-integrity` |
| L2-3 | 其他既有 Playwright（smoke / cuj / regression / history-subpath） | `apps/v3_eidos/tests/` | `cd apps/v3_eidos && npx playwright test` |

### L3｜人工瀏覽器抽測（釋出前必做，附佐證截圖）

最低抽樣：**每個開放組合（G/S/科/出版社）至少 3 題**，共 ≥ 29 組合 × 3 = **87 題**。每題驗證下列四點：

| 編號 | 驗證項 | 期望 |
|:--:|:--|:--|
| L3-a | 題目正常顯示（題幹、選項、情境、解析） | 無破版、無 AI 元評論殘留 |
| L3-b | **選項顯示順序 = JSON `options` 陣列順序** | 逐項比對 |
| L3-c | **使用者選「正解位置」 → 顯示為綠框正解** | 斷言「綠框文字 = JSON `options[answer_index]` 去前綴後」 |
| L3-d | **使用者選「非正解位置」 → 顯示為紅框 + 迷思診斷** | 迷思診斷內容與錯選項有語意關係 |

抽樣守則：
- 正解位置必須涵蓋 A/B/C/D 至少各一次（避免只測 A 時剛好 false pass）
- 每組合至少 1 題「正解不在 A」（根本杜絕類似 2026-04-19 bug 的 false negative）

## 三、禁止事項

1. **禁止**以「瀏覽器沒崩、能到達結果頁」代表測試通過。必須顯式驗證 L3-c（綠框 = 正解）。
2. **禁止**跳過 L3 抽測直接上版。即便 L1/L2 全綠，UI ↔ 資料的最終一致性只能由 L3 佐證。
3. **禁止**新增題庫格式卻不同步更新 `questionLoader.test.ts` 與 `verify_ui_data_integrity.mjs`。loader 的每個 code branch 都必須有對應測試。
4. **禁止**刪除或弱化 pre-commit 節點 3（UI 一致性）。若因效能考量需調整，必須先在本文件更新驗證標準並留下佐證。
5. **禁止**以「白盒邏輯模擬」（Node.js 手動跑 loader 邏輯比對 JSON）代替真實瀏覽器驗證——這只驗證資料，沒驗證前端顯示，2026-04-19 JOB-200 Phase 2 初版因此被退件。

## 四、多 Agent 環境要求（2026-04-19 JOB-200 經驗）

### 4.1 Antigravity

| 項目 | 最低要求 | 佐證 |
|:--|:--|:--|
| Node.js | **≥ 18**（vite 5 運行時需求） | Antigravity 預設 Node 14 無法啟 Vite |
| Chromium / Browser Subagent | 可啟動 | JOB-200 Phase 2 初版遭遇 Browser Subagent 通訊協議錯誤 |

**環境替代方案**（若系統 Node 為 14）：

```bash
# 使用 Cursor.app 內建的 Node 22 啟 Vite
/Applications/Cursor.app/Contents/Resources/app/resources/helpers/node \
  <專案路徑>/apps/v3_eidos/node_modules/.bin/vite \
  --host 0.0.0.0 --port 8080
```

### 4.2 Codex CLI

| 情境 | 必要參數 | 原因 |
|:--|:--|:--|
| 涉及本機 dev server（port 8080） | `--sandbox danger-full-access` | 預設 `workspace-write` 禁止開 port，Vite 會 EPERM |
| 涉及 Chromium / Playwright | `--sandbox danger-full-access` | 同上 |
| 純檔案讀寫 / 靜態分析 | `--sandbox workspace-write` 即可 | 不需網路 |

**Codex 呼叫範本**：

```bash
codex exec \
  --sandbox danger-full-access \
  --cd /path/to/eidosProject \
  --skip-git-repo-check \
  "$(cat jobs/JOB-XXX-prompt.txt)" \
  > scripts/orchestrator-logs/JOB-XXX-codex-output.log 2>&1 &
```

### 4.3 Cursor CLI

```bash
cursor agent --print --force --workspace . \
  "請讀取並執行派工單：jobs/JOB-XXX-*.md" \
  > scripts/orchestrator-logs/JOB-XXX-cursor-output.log 2>&1 &
```

Cursor 預設環境（Cursor.app 內建 Node 22 + 完整權限）無需特殊處理。

### 4.4 若環境無法啟瀏覽器

Agent 必須**明確回報為 BLOCKED**，不得退回用白盒邏輯模擬（違反 §三第 5 條）。由 Claude Code 在具備環境的機器上補驗，或於派工單改為專案 Owner 的本機環境重派。
