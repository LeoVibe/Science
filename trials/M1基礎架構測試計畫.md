# 🧪 M1 基礎架構測試計畫 (M1 Test Plan)

**最後修訂時間：** 2026-02-21
**存放路徑：** `trials/m1_test_plan.md`
**負責人/角色：** Antigravity (PM 定義情境)、Cursor (Dev 實作自動化)
**目標：** 在 Eidos `v1` (科學/原型)、`v2` (探索)、`v3` (理型) 開發期間，透過 **TDD 測試驅動開發**，確保系統的健壯性與向下相容性。此文件為開發端 (Cursor) 撰寫測試程式碼的「唯一真理依據 (Source of Truth)」。

## 1. 測試框架與環境建議

* **工具鏈建議：** `Vitest` 或 `Jest` (負責無頭邏輯測試)、`Playwright` 或 `Cypress` (負責 E2E / 視覺迴歸測試)。
* **測試目錄：** 
    * `/trials/unit_trials/`: 存放所有純邏輯、模組的單元測試。
    * `/trials/integration_trials/`: 存放各模組互動、以及舊版入口驗證的整合測試。
* **觸發時機：** 
    * CI/CD 流程：PR 建立時、推播至 main 分支時。
    * 手動觸發：透過 `web_manager` 的「一鍵自檢」。

---

## 2. 🧪 單元實驗 (Unit Trials) 情境定義

### 2.1 轉換儀器測試 (Parser & Tools)
主要測試位於 `shared/instruments/` 下的轉換工具（如 `convert-questions.js`）。
* **[UT-01] 正常解析轉換：** 
    * 輸入：符合預期的 Markdown 檔案。
    * 預期輸出：產生合規且資料正確的 JSON 物件。
* **[UT-02] 異常格式攔截：**
    * 輸入：缺少題號、格式錯亂或沒有答案的 Markdown。
    * 預期輸出：拋出包含具體錯誤行號與原因的 Exception，並阻擋寫出 JSON 檔案。
* **[UT-03] 答案精準比對功能：**
    * 輸入：選擇題的 `answer` 與 `options` 中的值不完全匹配（如多了空白字符）。
    * 預期輸出：拋出 Validation Error。

### 2.2 預期資料規格測試 (Schema Assertion)
確保已產生的 JSON Assets 完全遵守 `shared/forms/schema_contract.md` 規範。
* **[UT-04] 必填欄位驗證：**
    * 掃描 `question/platform/` 目錄下的所有 JSON。
    * 預期狀態：所有 `meta` 內的欄位與 `questions` 的核心結構皆存在，未能通過時測試應判定視為失敗 (fail)。

---

## 3. 🔗 整合與回歸實驗 (Integration & Regression Trials)

### 3.1 題庫載入整合
確保不同版本的 App 皆能順利讀取 `question` 共用資產。
* **[IT-01] Manifest 與實際檔案匹配：**
    * 情境：程式讀取 `/question/platform/.../manifest.json`，根據清單取得 `units.file` 名稱。
    * 預期：檢查上述檔案是否全部存於對應目錄下，沒有 404 (Missing Check)，也沒有多餘未登錄的檔案 (Orphan Check)。

### 3.2 向下相容回歸測試 (Backward Compatibility)
**對象：** `apps/v1_science`
* **[IT-02] V1 題庫載入路由：**
    * 情境：掛載 v1 的 Vite Server，發送請求至 `apps/v1_science/questions/.../L1.json` (由軟連結轉譯)。
    * 預期：返回 HTTP Status 200，並且返回合法的題庫陣列格式。
* **[IT-03] V1 選單生成機制：**
    * 情境：模擬初始化載入。
    * 預期：`apps/v1_science` 中的 `AllWrongQuestionsView.vue` 等核心元件，不應因為外部資料架構抽離而產生編譯錯誤或運行時異常 (Runtime Exception)。

---

## 4. 🚷 Edge Cases (特例邊界與偽數據)

此部分需由 **Gemini** 提供各類「非標準輸入」作為 Mock Data 供測試使用：
* **[EC-01] 極端題目長度：** 長度超過 1000 字的題目或詳解，UI 是否能正確捲動、Parser 會不會 Memory Out。
* **[EC-02] 特殊字元：** 檔案內包含罕見 HTML 標籤、跳脫字元 (`\n`, `\t`, `\"`) 時 JSON 生成的正確性。
* **[EC-03] 選項少於 4 個或為是/非題：** 當 `options` 長度為 2 甚至是無時，系統的處理機制與相容性。
