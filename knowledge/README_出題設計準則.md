## 🎯 一、 核心出題設計原則 (L4 高品質架構)

為了徹底解決「答案規律明顯」與「題目能力鑑別度不足」的問題，必須嚴格執行以下規範：

### 階段一：第一單元「除法」延伸出題 [/]
- [/] 依據 L4 策略升級 KangHsuan L1 (18題)
- [/] 依據 L4 策略升級 HanLin U1 (18題)
- [/] 依據 L4 策略升級 NanYi U1 (18題)

### 階段二：量測領域 (重量/容量) 研究與出題 [/]
- [/] 深度研究與綱要更新 (康 L2 / 翰 U2 / 南 U2, U6)

### 1. 🧠 認知層次分佈 (依據 PIRLS)
題目應依據以下比例進行分佈，確保涵蓋由淺入深的思考：
*   **事實提取 (30%)**：測驗具體細節、時間、人物屬性、公式定義。
*   **理解推論 (50%)**：測驗行為動機、事情轉折、因果關係、隱喻意涵、原理解釋。
*   **應用評論 (20%)**：測驗文章主旨、角色評價、結合生活情境的判斷與跨領域應用。

### 2. 🛡️ 高品質誘答項 (Plausible Distractors)
*   **排除荒謬項**：禁止邏輯不通或幼稚選項（如：肚子餓、選我選我）。
*   **邏輯誤導法**：合理使用「部分正確」、「因果錯置」或「常見迷思 (Misconception)」。

### 3. ⚖️ 答案分佈與字數均衡性 (防止冗長化)
*   **隨機化**：答案分佈需打散，嚴禁「正確答案集中」或「連續答案相同」。
*   **精簡與視覺均衡**：為防止學生視覺疲勞或利用長度盲猜，**選項文字必須精煉，不可為了詳盡解釋而過度拉長**。正確答案與干擾選項長度差異需控制在 10%-15% 以內，保持視覺上的等長對稱。
*   **防範冗長迴圈**：題目情境與解釋雖求完整，但在設計時仍應保持「短小精悍」，避免為了防堵漏洞而把文章塞得像閱讀測驗。
*   **語法對稱**：結構必須一致（全名詞、全成語、短句結構相似等），避免靠語感猜題。

### 4. 🎭 情境與解析結構
*   **解析價值**：必須點出「選項誤區」與「正確推導過程」。
*   **情境包裝**：盡可能結合生活情境（如：超市購物算數、生態觀察）。

## 🗂️ 二、 本目錄 (knowledge) 結構與技術規範

為了確保系統的統一自動化讀取與人工協作的一致性，各科的研究檔案與綱要必須嚴格遵守以下系統設計：

### 1. 檔案命名與路徑
本目錄僅存放**各科目/各年級的課綱研究與分析結晶**，不存放任何程式碼或 JSON。

- **標準路徑**：`knowledge/課綱研究/{學科}/`
- **標準命名**：`G{Grade}_S{Semester}_{學科}發展綱要.md`
- **範例**：`knowledge/課綱研究/社會/G5_S1_社會發展綱要.md` 或 `knowledge/課綱研究/數學/G4_S2_數學發展綱要.md`

### 2. 發展綱要內容核心區塊 (Section Schema)
每個年級學期的檔案，都必須具備以下核心架構：
- **[Metadata]**：對應的版本、更新時間與適用之出版版本（如：康軒、翰林、南一）。
- **[Stage Core Matrix] (階段性核心目標)**：描述該年級學期，該學科的核心學習認知門檻與教授觀點。
- **[Curriculum Matrix] (課程內容與發展矩陣)**：對應的課次、名稱主題。**必須將單純重點轉化為真實情境題材庫 (Scenario Pool)**。
- **[Misconceptions & Audit] (迷思與守衛點)**：定義該年段學生常犯的直覺錯誤、誘答盲點，以確保題庫的診斷價值。

### 3. 協作 SOP
**[1. 取得最新教材與驗證來源]** → **[2. 擴建發展綱要 (補足情境與迷思)]** → **[3. 引導自動化產題腳本]** → **[4. 執行品質評估腳本 (自動寫入等級)]** → **[5. 提交審閱]**

> [!CAUTION]
> **品質評分紅線規範**
> 1. AI **禁止**在 JSON 中手動填寫 `quality_level` 欄位，一律由 `evaluate_question_quality.js` 腳本自動計算寫入。
> 2. 每次產出或修改題庫 JSON 後，**必須立即執行腳本**：`node scripts/evaluate_question_quality.js <目標路徑>`。
> 3. L5 標記**僅限使用者**手動在 JSON meta 加入 `"verified_by": "expert"` 後再跑腳本生效。
