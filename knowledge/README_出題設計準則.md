## 🎯 一、 核心出題設計原則 (L4 高品質架構)

為了徹底解決「答案規律明顯」與「題目能力鑑別度不足」的問題，必須嚴格執行以下規範：

### 階段一：第一單元「除法」延伸出題 [/]
- [/] 依據 L4 策略升級 KangHsuan L1 (18題)
- [/] 依據 L4 策略升級 HanLin U1 (18題)
- [/] 依據 L4 策略升級 NanYi U1 (18題)

### 階段二：量測領域 (重量/容量) 研究與出題 [/]
- [/] 深度研究與綱要更新 (康 L2 / 翰 U2 / 南 U2, U6)

### 1. 🧠 認知層次分佈 (依據 PIRLS)
題目應依據以下比例進行分佈，確保涵蓋由淺入深的思考：
*   **事實提取 (30%)**：測驗具體細節、時間、人物屬性、公式定義。
*   **理解推論 (50%)**：測驗行為動機、事情轉折、因果關係、隱喻意涵、原理解釋。
*   **應用評論 (20%)**：測驗文章主旨、角色評價、結合生活情境的判斷與跨領域應用。

### 2. 🛡️ 高品質誘答項 (Plausible Distractors)
*   **排除荒謬項**：禁止邏輯不通或幼稚選項（如：肚子餓、選我選我）。
*   **邏輯誤導法**：合理使用「部分正確」、「因果錯置」或「常見迷思 (Misconception)」。

### 3. ⚖️ 答案分佈與均衡性 (防堵盲猜機制)
*   **答案分佈強制作業規範**：產出 JSON 時，`answer_index` 必須在 `0, 1, 2, 3` 中進行偽隨機分配，**嚴禁用同一個 index 填滿超過 40% 的題目**。此為不可跨越的鐵律。
*   **選項結構對稱原則 (Option Structural Symmetry)**：不可僅憑湊字數來達成選項等長。正確答案與錯誤選項不僅要字數相近，**「語句結構與句型」也必須對稱**。（例如：若正解是「因為...所以...」的因果結構，干擾選項也必須是看似合理的因果分析）。
*   **精簡與視覺均衡**：為防止學生視覺疲勞或利用長度盲猜，**選項文字必須精煉，不可為了詳盡解釋而過度拉長**。正確答案與干擾選項長度差異需控制在 10%-15% 以內。
*   **防範冗長迴圈**：題目情境與解釋雖求完整，但在設計時仍應保持「短小精悍」，避免把選擇題塞得像閱讀測驗。

### 4. 🎭 情境與解析結構
*   **解析價值**：必須點出「選項誤區」與「正確推導過程」。
*   **情境包裝**：盡可能結合生活情境（如：超市購物算數、生態觀察）。

### 5. 🧩 統整活動 (Unit Review) 專屬出題框架
*   **跨課文比較（Comparative）**：統整活動缺乏單一文本，題目應針對該單元的 3~4 篇課文進行橫向比較（例如：比較景點的共同文化意義；或相同情境下主角的不同應對方式）。
*   **單元核心價值歸納（Thematic Summary）**：題目應超越單篇課文的細節，測驗學生是否看出編者將這些課文放在同一個單元的「最高核心概念」（例如：從工藝推展到永續保育的大氣魄關懷）。

### 6. 🌐 各科目差異化品質模型與專屬鑑別門檻 (Multi-Track Quality Gate)
為避免將語文科（重長文閱讀）的品質標準強套在數理科（重計算邏輯）上造成誤殺與假警報，我們將全面採用「多軌判定系統」。

| 科目大類 | 對應學科 | 選項對稱性要求 (Symmetry) | 題幹長度/情境深度門檻 (Scenario) | 重點要求與特徵 (Core Value) |
| :--- | :--- | :--- | :--- | :--- |
| **文科思辨<br>(Text-Heavy)** | 國語、社會 | **嚴格**<br>(選項字數落差須小於 15%) | **嚴格**<br>(> 30字以上才能得高分，鼓勵>50字) | 要求情境豐富、干擾選項語句結構對稱、避免字面盲猜 (最長答案偏誤)。 |
| **數理邏輯<br>(Logic-Heavy)** | 數學、自然 | **豁免/放寬**<br>(若選項為短純數字、公式、單位，完全不計較長度偏差比) | **放寬**<br>(> 15字即給予情境滿分，因為重在數理邏輯運算) | 側重於計算邏輯、單位一致、誤導選項**必須**源自「常見計算錯誤」或「迷思概念」而非憑空捏造數字。 |
| **語文建構<br>(Lang-Learning)**| 英語 | **依題型浮動**<br>(單字/文法題放寬；閱讀題嚴格) | **依題型浮動**<br>(> 15字即可) | 對於單字選擇不強求長度對稱；重點在於時態、詞性、字因的「易混淆干擾度 (Distractor Validity)」。 |

## 🗂️ 二、 本目錄 (knowledge) 結構與技術規範

為了確保系統的統一自動化讀取與人工協作的一致性，各科的研究檔案與綱要必須嚴格遵守以下系統設計：

### 1. 檔案命名與路徑
本目錄僅存放**各科目/各年級的課綱研究與分析結晶**，不存放任何程式碼或 JSON。

- **標準路徑**：`knowledge/課綱研究/{學科}/`
- **標準命名**：`G{Grade}_S{Semester}_{學科}發展綱要.md`
- **範例**：`knowledge/課綱研究/社會/G5_S1_社會發展綱要.md` 或 `knowledge/課綱研究/數學/G4_S2_數學發展綱要.md`

### 2. 發展綱要內容核心區塊 (Section Schema)
每個年級學期的檔案，都必須具備以下核心架構：
- **[Metadata]**：對應的版本、更新時間與適用之出版版本（如：康軒、翰林、南一）。
- **[Stage Core Matrix] (階段性核心目標)**：描述該年級學期，該學科的核心學習認知門檻與教授觀點。
- **[Curriculum Matrix] (課程內容與發展矩陣)**：對應的課次、名稱主題。**必須將單純重點轉化為真實情境題材庫 (Scenario Pool)**。
- **[Misconceptions & Audit] (迷思與守衛點)**：定義該年段學生常犯的直覺錯誤、誘答盲點，以確保題庫的診斷價值。

### 3. Git 自動版本控制與題庫協作 SOP
**[1. 切換專屬特徵分支]** (例如: `git checkout -b feature/g3_math_batch2`) → **[2. 取得最新教材與驗證來源]** → **[3. 擴建發展綱要 (補足情境與迷思)]** → **[4. 引導自動化產題腳本]** → **[5. 執行品質評估腳本 (自動寫入等級)]** → **[6. git commit 提交 (受 Pre-commit Hook 檢驗)]**

> [!CAUTION]
> **品質評分與 Git 提交紅線規範**
> 1. AI **禁止**在 JSON 中手動填寫 `quality_level` 欄位，一律由 `evaluate_question_quality.js` 腳本自動計算寫入。
> 2. 每次產出或修改題庫 JSON 後，**必須立即執行腳本**：`node scripts/evaluate_question_quality.js <目標路徑>`。
> 3. L5 標記**僅限使用者**手動在 JSON meta 加入 `"verified_by": "expert"` 後再跑腳本生效。
> 4. **自動化攔截 (Pre-commit Gate)**：若 JSON 未達 L3 水準或含有 BIAS 盲猜漏洞，`git commit` 將會被強制中斷，必須返回修正才能入庫。
> 5. **提交命名規範**：Commit Message 請嚴格使用前綴標記，例如 `feat(question): 完成康軒 G5S2 L11 題庫產出，分數 4.19`。
