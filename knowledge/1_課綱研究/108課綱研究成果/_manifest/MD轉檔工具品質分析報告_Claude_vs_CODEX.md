## 三、實際內容比對（社會領綱 `1a-Ⅱ-1` 起 8 行）

### 案例 1：表格還原（兩者都成功，但精細度不同）

**A 輸出**：
```
| 1. 理解 及思 | a. 覺察 | 1a-Ⅱ-1 | 辨別社會生活中的事 | 1a-Ⅲ-1 | 舉例說明探究社會領 |
|          | 說明    |        | 實與意見。     |        | 域的意義及方法。  |
| 辨        |       | 1a-Ⅱ-2 | 分辨社會事物的類別 | 1a-Ⅲ-2 | 舉例說明在個人生活 |
```

**B 輸出**：
```
| 1.理解 a.覺察 | 1a-Ⅱ-1  | 辨別社會生活中的事 | 1a-Ⅲ-1  | 舉例說明探究社會領 |
| 及思 說明     |         | 實與意見。     |         | 域的意義及方法。  |
| 辨         | 1a-Ⅱ-2  | 分辨社會事物的類別 | 1a-Ⅲ-2  | 舉例說明在個人生活 |
```

→ 兩者編碼對得齊，但 B 把「1.理解 a.覺察」合在一格，較自然；A 把「a.覺察」獨立成欄。

### 案例 2：OCR「一→-」錯誤（A 全敗、B 全對）

**A 社會領綱**（line 15-19）：
```
| -、學習表現 ............. 6     |    ← OCR 錯誤
| （-）國民小學 ............ 6     |    ← OCR 錯誤
| -、課程發展 ............. 47    |    ← OCR 錯誤
```

**B 總綱目錄**：
```
一、課程類型與領域/科目劃分 ..................................... 9
二、課程規劃及說明 ............................................. 11
（一）國民小學及國民中學教育階段 ............................... 11    ← 全部正確
```

→ A 在社會領綱單檔有 100+ 個「一→-」錯誤；B 全部 11 檔加總 0 個。

### 案例 3：A 嚴重缺陷 — 表格內容「跨欄複製 8 次」

A 社會領綱 line 73 是個 8 欄表格，但 docling 把同一段內容**複製到所有 8 欄**：
- 同一段「-、國民小學教育階段」+ 後續 200 字內容，**一字不漏地重複 8 次**
- 這是 A 文件字元數多 +37% 但內容沒比 B 完整的主因

B 沒有這個問題（內容只出現一次，跨欄表格回退為純文字段落）。

## 四、各角度詳細評估

### 4.1 OCR 文字辨識品質 → **B 完勝**

A 系統性將中文「一」誤識為破折號「-」，影響：
- 章節編號：`-、學習表現` → 應為 `一、學習表現`
- 子節編號：`（-）國民小學` → 應為 `（一）國民小學`
- 學習階段：`第-學習階段` → 應為 `第一學習階段`
- 名詞中：「高-」、「附錄-」等

A 全 11 檔合計 **912 個**這類錯誤；B 為 **0**。

**對下游影響**：A 的編碼系統若要做精準匹配，需要先寫一個「-→一」轉換器才能正確 grep。B 直接可用。

### 4.2 結構化（Markdown 標題）→ **A 勝**

A 把章節用 `## 標題` 格式化，B 是純文字行。
- A 全檔 **4,392** 個 Markdown 標題
- B 全檔 **0** 個 `##` 標題

**用例**：用 VSCode 看 A 的 MD 會顯示完整章節大綱（Outline 面板）；B 不會。

但這個「優勢」可以後處理修補（用正則認出「壹貳參」「一二三」等中文章節序號加上 `##`）。

### 4.3 編碼抽取完整度 → **B 勝**

B 抽到的編碼比 A 多 **+54%**（9,000 vs 5,834）。

可能原因：
- B 表格還原較鬆散，每個編碼出現位置都被保留
- A 的表格還原雖較規範，但跨欄複製時編碼有時被切成兩段（無法被正則完整匹配）

**驗收**：兩者都 **7/7 命中** 7 條已知正解；但 B 的整體可抽取量更大。

### 4.4 表格還原 → 各有缺陷

**A 缺陷**：跨欄表格內容**重複 8 次**（見案例 3），製造大量冗餘字元。
**B 缺陷**：表格結尾有時掉出表格外變純文字行（如「變遷現象。」），需後處理修補。

**整體 B 較精簡乾淨**。

### 4.5 圖片處理 → **A 勝**

A 用 docling 標準輸出 `<!-- image -->` 註記圖片位置（1,312 個）。
B 只有 8 個（用中文「[圖]」標記）。

**用例**：若需追溯「這個概念配的是哪張圖」，A 較容易定位。對課綱研究地基來說重要性中等。

### 4.6 字元保真度 → **B 勝**

中文章節編號：A 1,497 / B 2,242（B 多 +50%）
全形羅馬數字：A 8,245 / B 9,210（B 多 +12%）

→ B 更忠實還原原 PDF 文字。

## 六、優劣綜合表

### A (Claude / docling) 優點
- ✅ Markdown 標題化（`##` 格式），VSCode 預覽友善
- ✅ 圖片佔位符完整（1,312 個 `<!-- image -->`）
- ✅ 表格切欄較規範（編碼欄、內容欄分開）
- ✅ 字元數高（但這是優點還是缺點要看用途）

### A (Claude / docling) 缺點
- ❌ **OCR「一→-」系統性錯誤 912 個**（嚴重）
- ❌ 跨欄表格**內容重複複製多達 8 次**（製造大量假字元）
- ❌ 中文編號保真度低（一、二、三常被吃掉或誤識）
- ❌ 編碼抽取量較少（-54% 比 B）

### B (CODEX) 優點
- ✅ **OCR 完美**（0 個「一→-」錯誤）
- ✅ 中文章節編號保真度高（+50%）
- ✅ 全形羅馬數字保留好（+12%）
- ✅ 編碼出現次數最多（+54% 比 A）
- ✅ 文字段落乾淨，無冗餘重複

### B (CODEX) 缺點
- ❌ 沒有 Markdown 標題（純文字章節）
- ❌ 圖片佔位符極少（8 個 vs A 的 1,312 個）
- ❌ 表格收尾有時掉出表格外（小瑕疵）

## 七、最終建議

**主要使用 B (CODEX)**，原因：
1. OCR 文字保真度遠高於 A，下游可信度高
2. 對 KL2/KL3/KL4 重做來說，「文字本身正確」遠重要於「Markdown 格式好看」
3. 編碼抽取量更全
4. 修補成本低（補 Markdown 標題容易，修 912 個 OCR 錯誤難）

**輔助保留 A**：
1. 作為圖片位置查詢的索引（`<!-- image -->` 標記）
2. 作為交叉驗證的第二來源
3. 結構化檢視時可用 A 看大綱

**後續行動**（建議在 KL2 重做 JOB 中執行）：
1. Phase E 結構化抽取改用 B 為來源
2. 已產出的 5 個結構化 MD（A 來源）標註為「A 版」，另用 B 重跑作為「B 版」
3. 比對兩版差異，作為品質保證

**不建議**：
- 直接拿 A 的內容做精準對照（OCR 錯誤會誤導）
- 拿 A 的字元數作為「內容更完整」的依據（37% 多出來主要是冗餘）
