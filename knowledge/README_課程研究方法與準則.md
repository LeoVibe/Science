## 🛠️ 一、嚴謹的 AI 實證研究流程與方法 (SOP)

為了確保題庫產出的信效度達到 L3 或 L4 標準，AI 進行新的課程研究或擴寫既有內容時，**嚴禁憑空推論或僅依賴標題出題**。必須遵循以下嚴謹的「實證紀錄」標準流程，並具體留存在各科的 `[年級學期]_[科目]_發展綱要.md` 中：

### 第一步：建立 [實證驗證區] (強制要求)
每研究一個新單元，AI 必須在該綱要檔案最下方建立對應的實證區塊。每一課的紀錄都會很長且具體，不可用簡單的幾句話帶過。

1.  **實質課文大意/節錄**：
    - AI **必須**透過搜尋引擎（如：`搜尋關鍵字 "國小 三下 國語 康軒 遇見美如奶奶 課文"`）去網路上尋找該課文的真實內容。
    - 取得後，需將重點的「課文段落、角色特徵、故事轉折或核心名詞」整理並轉錄於此。
2.  **考古題對照驗證**：
    - AI **必須**前往外部公信來源（如：學習方舟 `site:studyark.org` 或是各學校的教案、段考卷）搜尋相關資源。
    - 需明確記錄了「去哪個網站找到了哪些類型的題目」，例如：從 MAPS 提問單中發現老師特別強調人物特寫或推論觀察。擷取 1~3 題代表性考古題紀錄於此。
3.  **整合思考歷程 (L3 ➜ L4+)**：
    - AI 必須寫下**自身的出題策略**：說明要如何將上面找到的「課文」與「考古題」進行轉化？
    - 說明如何設計出能測驗深度理解的「誘答選項」？
    - ⚠️ **防止盲猜漏洞**：必須特別載明「干擾選項設計必須與正確選項等長，或刻意將干擾選項寫得更長」，嚴防「最長即正解」的低級失誤（否則會被品質過濾器阻擋）。

### 第二步：產出與品質標記
完成上述實質的資料蒐集與思考紀錄後，AI 才能開始依此草擬出符合 `manifest.json` 與 JSON 題庫規範的題目。完成後根據「二、評估標準」進行自我標記。
3.  **品質評估與標記**：
    - 完成研究後，根據「二、評估標準」進行各題與整體教材的自我評分。
4.  **文件化與發佈 (Git 提交)**：
    - 將研究成果產出至對應的發展綱要或研究紀錄檔中。**（注意：後續不需要在文件內手動維護諸如 `v4.2.0` 這種瑣碎版號，版號追蹤交由 Git History 處理；但請務必手動更新檔案開頭的「最後更新日期」以便人類協作者閱讀）**。
    - 確認無誤後，使用符合規範的 Git Commit Message（如 `feat(math): 補足 G3S2 L2 公斤公克實證區與 L4 題庫`）進行提交入庫。

## 🎯 二、評估標準 (Quality Rating Scale)

題庫深度與品質等級說明如下。每一道題目及每一課均可依照此架構進行評分標籤：

| 等級 | 核心依據 | 品質層次（執行標準） | 預期信效度 |
|:---:|:---|:---|:---:|
| **L1** | **課綱關鍵字** | **AI 逕行推論**： 僅依據標題產出，缺乏具體教材支撐，易生偏誤。 | 極低 |
| **L2** | **實質課文** | **基礎內容擷取**： 具備課文實證，但僅止於低階的記憶性或填空式試題。 | 中低 |
| **L3** | **考古題庫** | **規範化控管**： 經題庫比對驗證，依題目價值調整配重，並嚴格控制選項格式與隨機性。 | 中 |
| **L4** | **中心思想** | **核心目標對齊**： 精修題幹與選項語意，確保符合課程深度，具備極佳誘答力與測驗價值。 | 高 |
| **L5** | **專家認證** | **權威審定**： 經學科專家親自修撰或最終認證，確保教學實務與邏輯之極致嚴密。 | 極高 |

### 🔒 品質等級客觀門檻 (Objective Gate)

> [!CAUTION]
> **AI 產出題庫時，`quality_level` 欄位禁止手動填寫**，一律由 `evaluate_question_quality.js` 腳本自動計算寫入。違反此規範的 JSON 將被品質閘門攔截。

每個等級的認定必須滿足以下**客觀必要條件（缺一不可）**：

| 等級 | 必要前提條件 | 誰負責判定 |
|:---:|:---|:---:|
| **L1** | 無特殊條件限制 | 腳本自動 |
| **L2** | ☐ 對應發展綱要中有 Curriculum Matrix（課程矩陣） | 腳本自動 |
| **L3** | ☐ L2 條件 + 實證驗證區中有「考古題對照驗證」紀錄 | 腳本自動 |
| **L4** | ☐ L3 條件 + 實證驗證區中有「L4 轉化策略」+ 腳本自評 ≥ 3.5 分 | 腳本自動 |
| **L5** | ☐ L4 條件 + JSON meta 中 `verified_by: "expert"` + 使用者明確核准 | **僅限使用者** |

**紅線規範**：
1. AI 輸出 JSON 時 `quality_level` 欄位**留空或不填**，由腳本統一覆寫。
2. L5 的唯一合法路徑：使用者手動在 JSON meta 加入 `"verified_by": "expert"` → 再跑腳本。
3. 無實證驗證區紀錄的題庫 → 品質天花板強制為 **L2**。
