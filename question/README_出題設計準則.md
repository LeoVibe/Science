# 🧠 README：出題設計準則與品質規範 (Knowledge Base)

本目錄純粹存放「教育心理學、課綱分析與出題心法」。此份文件作為 Eidos 專案產出高品質題庫時的單一真相原則。為避免認知混淆，本文件依據「雙軌品質指標」，以分層次、分角色的角度循序漸進說明。

**最後修訂時間：** 2026-02-25

---

## 🎯 第一章：三維品質指標體系 (Tri-Dimensional Quality Metrics)

為兼具「知識萃取的累積性」、「AI 產出時的微調動能」以及「外部平台絕對的品質承諾」，本專案的評估系統採用「三維制」。這三個指標分別掌管了題庫生命週期的三個階段：**研究源頭 → AI 產題過程 → 最終成品守門員**。

| 比較維度 | 📖 研究成熟度指標 (RM) | 🎯 題目細緻度指標 (CQI) | 🛡️ 題庫嚴謹度指標 (QG) |
| :--- | :--- | :--- | :--- |
| **英文簡稱** | **RM** (Research Maturity) | **CQI** (Composite Quality Index) | **QG** (Quality Gate) |
| **指標類型** | **階段標籤制 (R0 ~ R3)** | **權重得分制 (0.0 ~ 10.0 分)** | **嚴格木桶制 (L1 ~ L5)** |
| **主要定位** | **【輸入品質】** 決定 AI 有多少真實細節可以參考。 | **【加工品質】** 作為出題時的 Best Effort 最佳化目標。 | **【輸出品質】** 網站前台展示與對外品質承諾。 |
| **主要對象** | 研究員、進行研究任務的 Agent | 出題任務的 Agent (如 Cursor) | 平台前端、系統 CI/CD 查核點 |
| **及格門檻** | 可彈性停留在任一階段，作為下個任務的起點。 | **單檔平均 6.0 分以上** (才允許入庫)。 | **缺一不可**。有一題犯規全檔無條件降級。 |
| **情境範例** | 「這單元我目前只找到考題，還沒發展出素養包裝策略，目前標記為 **R2**。」 | 「這題雖然結構不錯，但情境字數太少，CQI 只有 **4.5分**，需要重寫加長。」 | 「整份檔案有一題答案都是選項 A，觸發品質控管，QG 降級為 **L1** 阻擋 Commit。」 |

## 🤖 第二章：AI 出題協作準則 — 題目細緻度指標 (CQI)

本章節專供「實際產出題目」的 AI Agent 閱讀。AI 產出題目時，**絕對不需理會 L1~L5**，只需全力追求 **CQI 10.0 滿分**！

### 1. CQI 10 分制加權配比與設計規範

AI 在產題時，腳本會依照以下四大維度加總計分（滿分 10.0）：

#### 📐 A. 選項長度防猜機制 (滿分 3.0 分)
為了防堵學生利用「最長答案通常是正確的」等技巧**盲猜**，干擾選項的結構設計必須具備欺騙性，而不是僵硬地要求每個選項都一樣長。
*   **配分邏輯**：只要該題的**正確解答不是最長的選項**（或是四個選項完全等長），即可獲得 3.0 滿分。若正確選項恰好為最長，該項目將得 0 分。腳本也會在全檔層級控管「最長選項剛好是答案」的比例（上限 40%），超過將直接以 L1-BIAS 阻擋。
*   **設計心法 (嚴禁湊字品質控管，改用符合認知負荷 Brain-Friendly 三原則)**：
    為通過 CI 攔截，**絕對禁止**在句尾加上「這在文章中是一個很明顯可以發現的客觀事實」等無意義罐頭後綴。請改用以下三原則進行「實質改寫」，以提升學習者的神經認知效率：
    1. **同理心投射法 (活化情緒網路)**：在原本的動作後方加上角色的「內心獨白」或「情緒反應」（例如：將「大聲痛哭」擴寫為「*因為覺得很委屈而大聲痛哭，心裡暗自決定以後再也不要幫忙了*」）。這能活化孩童的心智理論，而非單純的行為延長。
    2. **合理化迷思法 (訓練邏輯除錯)**：設計一個「如果沒看懂文章，順著常理推斷極有可能發生的錯誤反應」。利用「因果倒置」或「情緒錯位」建立具備說服力的誘答項，取代容易造成閱讀記憶混亂的「細節錯置」陷阱。
    3. **語氣延展法 (消除神經視覺雜訊)**：不再追求完全等長，如果四個選項本身就極為簡短，請利用兒童熟悉的語氣助詞（例如：「...呢！」、「...才對。」）或情緒副詞（例如：「真的...」、「竟然...」）來自然延長尾音。
    > 🚫 **絕對禁止的「空白作弊」行為：** 嚴禁在選項的開頭、中間或結尾加入**任何半形空白 (` `) 或全形空白 (`　`)** 來試圖讓長度變得一樣。這是一個非常愚蠢的做法，不僅會造成排版跑位，還會產生視覺雜訊。目前品質驗收腳本 (`evaluate_question_quality.js`) 已經實裝了自動清洗機制，所有作弊的空白都會在驗證時被強制剃除，這只會導致你的題目原形畢露並被依 `L1 (BIAS)` 阻擋。請務必使用「真實的文字內容」來擴寫誘答！

#### 🌍 B. 情境深度與字數 (滿分 3.0 分)
禁止把重點寫成考卷條列式，盡可能結合真實生活情境（超市購物、新聞報測、角色對話）。題幹的字數直接決定情境的發揮空間。
*   **降低工作記憶負荷的寫法**：長題幹不應是密集的陳述句，必須包含**「熟悉的生活場景標籤」**（例如：*在超級市場裡...*、*下課鐘聲響起時...*），或善用「引號對話框」建立角色扮演狀態，以降低兒童閱讀長文時的認知消耗（Cognitive Load）。
*   **配分邏輯**：
    *   **文科思辨 (國語、社會)**：題幹大於 **50 字**得 3.0 滿分；30~50 字得 1.5 分；低於 30 字得 0 分。
    *   **數理/語文 (數學、自然、英語)**：題幹大於 **25 字**得 3.0 滿分；15~25 字得 1.5 分；低於 15 字得 0 分。

#### 🧠 C. 認知層次涵蓋 (滿分 2.0 分)
題目 (的 `taxonomy` 屬性) 必須覆蓋不同的思維維度，不應淪為全盤的知識背誦。AI 在出題時，強烈建議依循四大認知層次進行題型包裝設計：
1. **記憶提取 (Literal)**：測驗字音字形、詞義解釋與直接的課本事實記憶。題幹可以短，難度低。(基礎)
2. **邏輯推論 (Inferential)**：測驗因果倒置、流程還原與行為動機解釋。(進階)
3. **場景判斷 (Contextual / Applied)**：測驗能否將課文概念「遷移 (Transfer)」至另一個完全不同的生活日常情境。(高階)
4. **價值思辨 (Critical / Argumentative)**：測驗換位思考、批判性評價角色行為，或統整文本的核心寓意。(高階)

*   **跨年級動態配比建議 (Dynamic Ratios)**：
    為避免低年級認知超載或高年級缺乏挑戰，應依據學齡段皮亞傑認知發展論調整上述四層次的配比。
    *   **低年級 (G1~G2)**：`6-3-1` (60%記憶、30%推論、10%淺層場景，嚴禁價值思辨)。
    *   **中年級 (G3~G4)**：`4-4-2` 或 `3-4-3` (強化因果推論，導入生活場景與適度思辨)。
    *   **高年級 (G5~G6)**：`2-3-5` 或 `1-3-6` (大幅強化跨學科遷移、反向詰問與道德思辨)。

*   **配分邏輯**：
    *   **邏輯推論、場景判斷、價值思辨 (`inferential`, `applied`, `critical`)**：得 2.0 滿分。這類題型必須結合情境或推導。
    *   **記憶提取 (`literal`)**：僅得 1.0 分。測驗具體細節、公式。

#### 🛡️ E. 情境設計品質控管與心理防禦平衡
當我們設計長題幹 (Contextual / Critical) 的情境題時，存在兩個易被忽略的隱性地雷：
1. **閱讀耗損 (Reading Fatigue)**：
   - 避免讓小學兒童直接閱讀「一大坨敘述性長文」。
   - **解法**：強制使用「模組化切割」。例如直接掛上 `【在學校大掃除時】` 的情境標籤，或採用「對話框結構」：`小明：「...」`，藉此降低工作記憶負荷。
2. **社經地位與城鄉偏見 (Cultural Bias)**：
   - 測驗不應該懲罰「沒有都市生活經驗的學童」。
   - **解法**：嚴禁設定過度商業化或高社經常見情境（如去機場搭飛機、逛百貨公司買名牌）。「場景判斷」的題幹應侷限於普世經驗（如：家庭勞務、校園人際、大自然觀察）。
    *   具備有效的針對性錯題迷思診斷標籤 (`commonMisconception` 或 `scenario`)：得 0.5 分。
    *   具備有價值的詳細推導解析 (`explanation` 超過 10 個字，清楚點出盲點)：得 1.0 分。
    *   基本的題目 ID 格式正確：得 0.5 分。

> **⚠️ AI 出題作業門檻 (The 6-Point Rule)**
> 當你產出一份題庫 JSON 後，你必須執行 `node scripts/evaluate_question_quality.js`。
> 若整份檔案的平均 CQI 出來 **低於 6.0 分**，代表你設計的情境太短、長度嚴重失衡或缺乏解釋，請立刻反省重出！

### 2. 特殊出題框架：統整活動 (Unit Review)
遇到單元統整活動缺乏單一篇章時，請使用：
*   **跨課文比較 (Comparative)**：拿該單元 3~4 篇一起比（例如同情境下主角不同應對）。
*   **單元核心價值歸納 (Thematic Summary)**：測驗學生是否看出編者將這些課文放在同一單元的最高核心理念。

## 🛡️ 第三章：平台防線機制 — 題庫嚴謹度指標 (QG)

本章節用來說明腳本是如何替最終輸出到 GitHub 與前台的題庫進行「標籤分級」。這是最嚴格無情的安全閘門，一律由腳本自動賦予，**人類或 AI 均不可手動塗改 JSON 內的 `quality_level` 欄位**。

### QG (品質達標等級) 閘門標準 (木桶原理)
- **L1 (BIAS)**：答案分佈嚴重不均 (例如單一選項 > 60%)、出現最長選項盲猜漏洞，或基礎格式損壞。**觸發此條件將無條件降級並直接阻擋 Git Commit**。
- **L2 (基礎及格)**：具備完整題目、選項與解答，符合基本的題型格式，但不保證解析完整性與真實生活情境。
- **L3 (標準題庫)**：除滿足 L2 外，全檔幾乎每題都**必須具備有價值的 `explanation`（詳解）**，且符合該科目的**選項長度品質控管要求**（全檔不得有超過 40% 的題目正確解答為最長選項），且沒有任何答案分配異常。
- **L4 (素養導向)**：除滿足 L3 外，`scenario`（生活真實情境）與文本描述不可為空，且**字數必須達到該科目的情境深度門檻**，展現將考點包裝於生活或跨域情境中的能力。
- **L5 (專家評鑑)**：除滿足 L4 外，必須包含 `commonMisconception`（常見迷思診斷），並經由人工/專家手動於 meta 標註 `"verified_by": "expert"` 方可過關。

## 📖 第四章：發展綱要的研究成熟度模型 (Research Maturity Stages)

課綱與教材的研究是一個**「漸進累積」**的過程。我們不要求一次性寫出完美的 L4 轉化策略才能開始出題。相反地，只要如實記錄當前的研究進度，我們隨時可以在低成熟度階段先產出基礎題（L2/L3）進行測試，再隨時間不斷深化研究，最終產出可對外釋出的素養題（L4+）。

為了明確區隔當前單元的研究狀態，請在發展綱要的 `[實證驗證區]` 中，依序推進並標示以下**四個成熟度階段 (R0 ~ R3)**：

| 狀態標籤 | 定義階段 | 具體達成條件與紀錄重點 | 預期能產出的題庫上限 |
| :--- | :--- | :--- | :--- |
| **[R0] 骨架期**<br>*(Outline)* | **確認範圍** | 僅完成 `Curriculum Matrix`。知道單元名稱、對應知識點，但缺乏任何細節。 | 無法出題（缺乏具體實證） |
| **[R1] 素材期**<br>*(Material)* | **取得原始素材<br>*(大加分項)*** | **成功取得或還原該單元的核心素材。** <br>• **語文科**：爬取或推斷出原始課文段落、單字表、句型文法結構。<br>• **理科**：取得詳細的教學指引步驟或實驗觀察紀錄。<br>*（註：若素材難以取得，可利用網路開放資源近似替代，並註明來源。）* | **L2 基礎題**<br>（能測驗背誦與基本理解，但缺乏品質控管） |
| **[R2] 考古期**<br>*(Baseline)* | **確立靶心與迷思** | **收集傳統考法與學生常犯錯誤。**<br>• 紀錄均一平台或過往段考的典型題型（知道傳統都怎麼考）。<br>• 明確記載該單元學生的「典型迷思」（例如：進位算錯、不知道餘數要小於除數）。 | **L3 標準題**<br>（能覆蓋知識點，具備基礎解析） |
| **[R3] 轉化期**<br>*(Strategy)* | **L4 素養轉化策略** | **確立如何將 R2 的死板考法，包裝成真實生活情境。**<br>• 定義「情境包裝手法」（例如：把除法變成超市預算分配）。<br>• 定義「高階誘答公式」（例如：故意設計一個選項是『忘記處理餘數』的正確數值）。 | **L4/L5 素養題**<br>（具備情境深度與迷思診斷，可發布） |

**🛠️ 協作與累積原則：**
1. **不強求一步到位**：若網路搜尋只找到課文（達 R1），可以先留下紀錄並中斷任務，交由下一個循環的任務來發想 R3 策略。
2. **凡走過必留下痕跡**：AI 在執行任何階段的研究時，必須將外部網頁的參考資料（如：某篇教育論文對迷思的探討、某篇課文的原文）完整寫入 `.md` 檔中。**發展綱要本身就是大腦記憶區**，避免重複搜尋。
3. **品質對應**：研究做到哪個階段，就產出對應等級的題目。沒有 R3 的策略支持，AI 極難憑空幻想出達標的 CQI 9.0+ 題目。

## 🗂️ 第五章：系統架構與技術協作規範

各科的研究檔案與綱要必須嚴格遵守以下系統設計：

### 1. 知識庫檔案命名與路徑
本目錄僅存放**各科目/各年級的課綱研究與分析結晶**，不存放任何程式碼或 JSON。
- **標準路徑**：`knowledge/課綱研究/{學科}/`
- **標準命名**：`G{Grade}_S{Semester}_{學科}發展綱要.md`
- **範例**：`knowledge/課綱研究/社會/G5_S1_社會發展綱要.md`

### 2. 發展綱要核心區塊 (Section Schema)
為了能讓評分腳本判定研究品質達到 L4 天花板，所有的《發展綱要》必須嚴格包含以下五個核心區塊：
- **[Metadata]**：適用之出版版本（如：康軒、翰林）、年級與學期。
- **[Stage Core Matrix] (階段性核心目標)**：描述該學科的認知門檻。
- **[Curriculum Matrix] (課程內容與發展矩陣)**：必須將單純重點轉化為「真實情境題材庫 (Scenario Pool)」。
- **[Empirical Validation] (實證驗證區)**：AI **必須**透過使用網頁搜尋工具，查閱真實的最新課本目錄與近五年期中/期末考古題，並將比對與趨勢結果記錄於此。嚴禁在沒有搜尋的情況下憑空捏造。
- **[L4 Conversion Strategy] (L4 轉化策略)**：定義如何從基礎考點轉化為符合 QG L4 (情境長度、品質控管、認知層次等) 的具體策略。

### 3. 自動版本控制與題庫協作 SOP (包含專家審核漏斗)
**[1. 釐清需求與切換分支]** (例如: `git checkout -b feature/g3_social`) 
→ **[2. 執行外部網路研究]**：使用搜尋工具查找各家版本最新目錄、課文主題與考古題。
→ **[3. 建置並完善發展綱要]**：依據上述真實資料，填寫五大 Schema 核心區塊。
→ **[4. 引導 AI 進行加權得分式出題]** (目標 CQI>6.0) 
→ **[5. 執行品質評估腳本]** (自動品質控管寫入 L 等級) 
→ **[6. git commit 提交]** (受 Pre-commit Hook 檢驗)
→ **[7. 專家後台審查與精選]** (新增)：領域專家登入系統後台，進入題庫單元審查介面，逐題確認品質後手動「上架」優質題，劣質題則予以「下架」。

- *提交命名範例*：`feat(question): 完成康軒 G5S2 L11 題庫產出，平均細緻度 CQI: 8.42`

### 4. 題庫審查漏斗機制 (Question Curation Workflow)
為了確保最終呈現給學生的題目品質，系統禁止 AI 產生的題目「零把關直通前台」。
1. **單題狀態管控**：每題 JSON 生出時具備 `is_active` 布林值（預設由系統判讀，且前台解析器嚴格只過濾 `is_active !== false` 的考題）。
2. **廣泛生成與後台精選**：AI 的指引是「多出一些題目」，發散思維產生候選題；隨後人類專家利用後台的「特定單元題庫審查介面 (Unit Curation View)」，比對每題的 CQI (細節度) 與 QG (嚴謹度)，一鍵進行上架與下架。
3. **動態回饋修正**：該介面未來也作為收集「學生作答反應不佳」的回報看板，讓專家能第一時間修改或下架不合適的錯題。
