# `audit_rm_vs_ql.mjs` — 素材成熟度(RM) vs 題目品質(QL) 矛盾稽核

`last_updated`: 2026-06-16
`updated_by`: Claude Code (claude-opus-4-8[1m])

## 目的

依 `docs/superpowers/specs/2026-06-16-題庫評估規則v2-課文非必要-design.md` 的「素材天花板」原則，
逐庫檢查題目品質標籤（`quality_level`）是否超過其素材成熟度（RM）所允許的天花板。
這是 v1 漏洞（RM0/RM2 題能標 QL4 上線）的程式化防呆。

## 核心邏輯

1. **遍歷題庫**：`question/platform/{G3..G6}/{Chinese,SocialStudies,Science,Math,English}/{S1,S2}/{HanLin,KangHsuan,NanYi}/`
   下的課級 JSON（`*_L*.json`），排除 `_new.json`／`manifest`／`_index`／`backup`。

2. **讀素材 RM**（國語/社會/自然）：到對應的
   `knowledge/1_課綱研究/{科中}/{年中}{學期中}/{版中}/` 找
   `KL4_{年中}{學期中}_{版中}_L{n}_*_單課研究紀錄.md` 與 `…_考古題與討論.md`，
   各自讀**檔頭「研究成熟度」那一行**的 `RM[0-9]`。
   **該課 RM = 兩檔較高者**（考古題與課文地位對等，有其一即拉高素材）。

3. **RM → 天花板 QL**：

   | RM | 天花板 |
   |:--:|:--:|
   | RM0 / RM1 | QL1 |
   | RM2 | QL2 |
   | RM3 / RM4 | QL4 |

4. **逐課比對**：該課題目的 `quality_level` 數字 **> 天花板 QL 數字 → 該課矛盾**；
   一庫只要任一課矛盾即判為**矛盾庫**。

5. **數學／英語**：走 KL3 體系，標 `KL3體系·另議`，不判矛盾（但仍統計 QL 眾數）。

## 重要實作決定

- **RM 取自「成熟度」標註行**：實際有兩種格式（survey 2026-06-16）——
  自然/社會用檔頭 `**研究成熟度**：RMn`；國語用 RC-06 檢核行
  `單課研究成熟度標註為 RMn`（約第 64 行，故需掃全檔）。本腳本鎖定**含「成熟度」的行**
  再抓 `RM[0-9]`，同檔多行取最大值。錨在「成熟度」可避開路線圖句（`升級至 RM2` 不含「成熟度」）
  與檢核註記（`出題上限：QL1（RM0 禁止出題）` 不含「成熟度」）的誤判。
- **「兩檔皆缺 / 皆無 RM 標記」不臆造 RM0**：歸入獨立的 **`素材無法判定`** 桶，
  與矛盾庫分開計數。只有「檔在、RM 讀到、QL > 天花板」才算實證矛盾（避免局部推全部）。
- **NFC 正規化**：macOS 檔名常為 NFD，與程式組出的 NFC 前綴比對會 false negative。
  所有檔名比對前一律 `s => s.normalize('NFC')`。

## 用法

```bash
node scripts/audit_rm_vs_ql.mjs          # 人讀彙總（每庫一行 + 彙總 + 矛盾庫清單）
node scripts/audit_rm_vs_ql.mjs --json   # 機讀 JSON（summary / conflictLibraries / rows）
```

人讀輸出每庫一行：`庫名 | 課數 | JSON QL眾數 | 素材RM範圍 | 判定`，
判定值為 `矛盾`／`素材足`／`KL3體系·另議`／`素材無法判定`。
